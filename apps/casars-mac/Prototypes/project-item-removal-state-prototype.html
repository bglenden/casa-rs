Removal behavior prototype

Design question: Can one Finder-like removal model safely cover notebooks, datasets, files, and folders—while still offering immediate deletion when storage pressure matters?

Project items

Finder convention: right-click exposes both actions; ⌘ ⌫ moves the selected item to Trash. Immediate deletion has no keyboard shortcut here.

Removal review

Walkthrough: remove a duplicated tutorial notebook

  1. Select TW Hya First Look (copy) and choose Review removal….
  2. Move to Trash removes only the visible Markdown notebook. Tutorial support files remain dormant so Finder’s Put Back can restore it cleanly.
  3. Delete Immediately… also removes notebook-owned tutorial copies and visualization assets. Execution receipts and scientific products remain as provenance.

Walkthrough: recover working storage

  1. Select uid___A002_Xc123.ms. The review shows its 84 GB size and the notebook that refers to it.
  2. Move to Trash is reversible, but free space remains unchanged while the dataset stays in system Trash.
  3. Delete Immediately… reclaims 84 GB now. The tutorial becomes “dataset missing”; the notebook and task history remain.

Walkthrough: ordinary files and unsafe targets

  1. An ordinary project file or folder uses the same review and actions.
  2. Recognized notebooks and datasets route through their semantic cleanup rules even when selected in Files.
  3. The project root, managed .casa-rs state, out-of-project paths, and items used by a running task cannot be removed.
