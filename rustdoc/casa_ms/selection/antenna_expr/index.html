CASA’s antenna (baseline) selection expressions, ported from casacore.

resolve_antenna_selector parses the antenna= text of an MSSelection and resolves it against the ANTENNA table into a BaselineSelection: for every ordered (ANTENNA1, ANTENNA2) pair of a MAIN row, whether CASA would select that row. It follows casacore at commit aaf72eb7 (the casacore of CASA 6.7.6.14): the scanner ms/MSSel/MSAntennaGram.ll, the grammar MSAntennaGram.yy, the selection logic MSAntennaParse.cc and the name lookups MSAntennaIndex.cc. Where these have quirks, CASA’s behaviour is kept and the quirk is noted below.

§Expressions

An expression is one or more terms separated by ;. A term is a baseline form applied to antenna lists, a baseline-regex list or a baseline-length list, optionally negated by a leading !.

Every name, pattern, station or ID that matches nothing is an error, raised once the whole expression has been read (reportError, MSSelection.cc:858-864), as are scanner and syntax errors, units that are not lengths and regexes that do not compile. The empty string is no constraint (MSSelection.cc:590); text of only blanks is a syntax error.

§CASA quirks this port keeps

  • A purely numeric item is a NAME first: with an antenna named "3", 3 selects that antenna, not ID 3; only its first such row is kept (.yy:352-355). A range looks up std::ostringstream decimal names, so 01~02 looks up "1" and "2" while a lone 01 looks up "01".
  • Integers are read with atoi: 4294967296 is antenna 0 (glibc keeps the low 32 bits). A range a~b whose length b - a + 1 is below zero or overflows Int (0~2147483647) is an error, as the C++ Vector allocation fails; a range reaching past the last antenna selects the antennas that exist without complaint.
  • !T also selects every autocorrelation T excludes: !ea01 selects ea01’s own autocorrelation, since T masks autocorrelations before the negation (.cc:84-91).
  • ; is not commutative: ea01;!ea02 is (ea01 baselines) AND NOT (ea02 baselines), but !ea02;ea01 is (NOT ea02 baselines) OR (ea01 baselines).
  • A leading ^ inside a regex or pattern is negation, not an anchor: /^ea0[12]/ selects every antenna but ea01 and ea02.
  • Patterns and regexes fall back to STATION per antenna; exact names fall back to STATION only when no NAME matches at all.
  • A baseline regex is matched against the ordered string NAME(ANTENNA1)&NAME(ANTENNA2), so /ea01&ea02/ selects the rows with ANTENNA1 = ea01 and ANTENNA2 = ea02 but not the reverse; one that matches nothing selects nothing silently (.cc:299-308).
  • Length forms: <x and >x move the bound by 1e-9 m; a range of plain integers with a unit (100~200m) is an antenna-ID range followed by a stray unit, hence a syntax error: write 100m~200m or 100.~200.m.
  • Concatenated quotes keep their inner quotes ("ea"'01' is the pattern ea"'01, .ll:69-75).

§Not ported

  • ECMAScript backreferences, lookahead and \u escapes in regexes are refused: the regex crate has none of them.
  • ANTENNA POSITION is read as ITRF, as everywhere in casa-ms; CASA converts other reference frames with MPosition::Convert.
  • The side lists MSSelection::getAntenna1List, getAntenna2List and getBaselineList are not produced; only the row predicate is.
  • Messages follow CASA’s wording but not its character positions exactly.
