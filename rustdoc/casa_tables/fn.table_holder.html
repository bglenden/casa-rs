pub fn table_holder(table_dir: &Path) -> Result<Option<TableHolder>>
Expand description

Where the table at table_dir is held open, tested without opening the table or taking a lock: by a handle in this process that holds its table.lock, or by another process, if a write lock on the lock file’s in-use byte would be refused. A handle in this process is reported first, as casacore’s TableUtil::canDeleteTable refuses a table still open in this process before it asks isMultiUsed. Another process is tested for only when this process holds no handle on the lock file, so the descriptor opened for the test holds no lock that closing it would release.

None means that no holder was detected, not that none exists. A handle opened without locking (casacore’s NoLocking, and casa-rs’s Table::open) leaves no mark, nor does a table casacore opened without a lock file, so neither is seen; casacore’s own check does not see them either. And the answer is a snapshot: a process can open the table as soon as it is given.

C++ equivalent: TableUtil::canDeleteTable’s “still open in this process” test and Table::isMultiUsed (LockFile::isMultiUsed), which Table::deleteTable and Table::rename consult before they act.

§Errors

The lock file exists but cannot be opened or tested.
