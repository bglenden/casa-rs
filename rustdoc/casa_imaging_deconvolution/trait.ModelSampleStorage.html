Expand description

Storage for one model generation’s canonical samples.

The model generation retains this handle exclusively. Implementations must preserve exact values and support bits, check every requested range, and report I/O failures. Reads do not resize a cache beyond the physical plan’s admitted capacity. Only owner-queued increments may mutate a logically immutable generation on first access. External handles must not mutate it. The trait is the dependency boundary for casa-imaging-runtime’s paged model, the second implementation beside the resident storage here.

fn apply_updates( &self, updates: &[ModelSampleUpdate], precision: NumericPrecision, bound: f64, ) -> Result<f64, ModelLifecycleError>

Apply sorted sparse increments within one admitted window, returning the largest updated magnitude. The owner serializes updates to overlapping windows; disjoint windows may execute concurrently. Implementations must batch backing access, preserve support, and propagate partial-write errors.
