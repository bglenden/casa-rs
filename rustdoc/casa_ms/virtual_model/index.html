Source
Expand description

CASA’s virtual model: a field’s model visibilities held in the MeasurementSet as a recipe instead of a MODEL_DATA column (refim::VisModelData, synthesis/TransformMachines2/VisModelData.cc of CASA 6.7.6). tclean with savemodel='virtual' writes one (SIMapperCollection::saveVirtualModel, through VisibilityIteratorImpl2::writeModel), and CASA’s visibility iterator predicts from it in place of MODEL_DATA (VisModelData::getModelVis): mstransform(datacolumn='model'), the calibrater’s solves and plotms read it; delmod lists and clears it.

§Layout

A model is filed under a key, model_<f>[_<f>…], naming the fields it covers in ascending order, and each of those fields points to it with a keyword definedmodel_field_<f> holding the key. When SOURCE has rows and the first field’s SOURCE_ID is not -1, the key and the pointers are SOURCE keywords, the key’s an Int naming the first SOURCE row of that source, and the model record is that row’s SOURCE_MODEL cell (the column added when SOURCE lacks it); otherwise both are MAIN keywords, the key’s holding the record (VisModelData::putModelRecord, putRecordByKey). CASA 6.7.6 measured on refim_twochan.ms (SOURCE rows) and refim_point.ms (none) writes exactly this.

The record of version 2 (VisModelData::putModel with an index combination) is {version: 2, numft: n, ft_0: …, numcl: m, cl_0: …}, its entries (VirtualModelEntry) each {version: 2, indexcombination, channelselection, container, type}: the (FIELD_ID, spectral window, SCAN_NUMBER, STATE_ID) combinations it predicts for, the channels the writer selected, the serialized FTMachine or ComponentList that predicts, and "ftmachine" or "componentlist". A reader matches a visibility buffer’s combination against indexcombination; nothing reads channelselection back.

Clearing follows VisModelData::clearModel: every field’s model when no field is named (crate::scratch_columns holds that), else each named field’s model, or only its entries’ combinations of the named spectral windows (clear_virtual_model). As there, casa-rs deletes the FT_MODEL* image tables of a removed model, but only those in the MeasurementSet’s or its SOURCE’s directory, so that a path in a record never deletes anything else. A multi-MS is written as one table, where CASA writes each part.

put_virtual_model
Add entry to the virtual model of its fields, as CASA’s VisModelData::putModel (version 2) does: the record already filed under the entry’s key, else the record a SOURCE row in use for the first field’s source holds, gains the entry after its others when incremental or when it had a record to add to; otherwise (a new record, not incremental) the record is the entry alone, and the images the old record named are deleted. Without incremental an entry of the old record covering one of the new combinations is removed first (addToRec). The record is then filed as the module states, and every field the entry covers points to it.

virtual_model_image_path
