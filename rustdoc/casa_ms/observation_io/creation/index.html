casa_ms::observation_io

Module creation 

Source
Expand description

Creating a MeasurementSet v2 from observations through the observation boundary (CreationPlan): each input is read as batches like any consumer reads it, and the MeasurementSet is created from those batches and the inputs’ catalogues.

A plan first inventories what the MeasurementSet cannot hold (a Loss) and refuses, before any byte is written, every loss the caller did not accept (CreationOptions::accept): creation never drops information silently, nor states what an input did not hold without saying so (Loss::SigmaDerived). What it keeps it keeps exactly: every acquisition, its flags (row flags folded in), weights, UVW and time auxiliaries, and every selected data group. Padding, a grid cell no acquisition filled, stays padding: a flagged row of NaN data and weights, or, by the declared policy that reproduces an original sparse MSv2, no row (PaddingRows).

The selected data groups of a partition are read in lockstep, one traversal each sized to the same whole times per batch (the first with every role, the others their visibilities only), so the writer writes every column of a time range together.

What making and writing a plan hold is admitted against CreationOptions::memory_bytes before it is allocated (MemoryCharges); a batch must hold one integration of every selected group (CreationOptions::batch_bytes).

The conversions between MSv2 and MSv4 (convert, with the msv4 feature) share this machinery; converting into an MSv2 is a plan over one input.
