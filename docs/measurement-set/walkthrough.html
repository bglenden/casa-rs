01 · The goal

One scientific boundary.
Two storage worlds.

Imaging, calibration, and flagging should consume the same scientific structures whether the data came from a CASA table or an MSv4 array store.

The adapter returns the bound layout/traversal, read/decode/copy costs and resource limits, or an explicit error. This negotiation happens before numerical iteration.

→

Proposed common boundary. Production computation and I/O run natively, without a Python runtime.

The processing planner knows how its operation will consume data and sends that access pattern through the common source interface. The adapter knows the storage geometry and organizes I/O accordingly. The algorithm's numerical loops consume the resulting views; they do not negotiate I/O per value.

Common after binding

Select → bind access → receive batches → compute → submit changes → finish.

Specific at creation

MSv2 storage managers and tiles; MSv4 chunk geometry, codecs, and schema metadata.

This is a walkthrough of a proposal. The shared API is not implemented or frozen. MSv2 + MSv4 is the agreed scope; MSv3 and XRADIO image persistence are deferred.

02 · Vocabulary

Keep scientific grouping, I/O, and work separate.

A physical chunk does not define a calibration solution, a kernel invocation, or the amount of work assigned to a thread.

Scientific meaning

Partition & scientific group

A partition has a compatible spectral, polarization, and observation context.

A scientific group is what an algorithm treats together, such as one solution interval. It can cross partitions.

Data movement

Chunk & visibility batch

A chunk or tile is a physical decode/update unit.

An visibility batch is the bounded aggregation delivered by the adapter. It may span many chunks.

Execution

Window & work unit

A compute window is the part of a batch a kernel processes.

A work unit runs one or more windows on one worker or a cooperating worker group.

Several stored chunksRead/decode efficiently
→
One larger visibility batchAmortize adapter work
→
Window A → worker 1
Window B → workers 2–3

Relationships are flexible. A scientific group may need fragments from several batches, and one batch may feed several groups.

This separation lets MSv4 use larger native aggregation without making every kernel use a large scratch buffer. A data group, introduced next, is another concept: it associates the arrays that describe one visibility product.

Visibility batch is the provisional name for the common intermediate. “Observation block” has an observatory meaning; “chunk” is reserved here for physical storage. The batch can contain only requested metadata/flags when visibility values are unnecessary.

03 · Before reading payloads

Open a catalogue of scientific meaning.

The first common structure describes antennas, spectral windows, correlations, fields, sources, and available data products. Selection uses these meanings.

Observation cataloguePartitions · antennas/feeds · SPWs · correlations · fields/sources
→
Selected data groupVisibility + flags + weights + UVW + field/source context

A data group might represent raw, corrected, or model visibilities. These labels are conveniences; the actual array associations are explicit. Two groups may share a flag or weight variable, which matters when writing.

CaseProposed representation
Mosaic fieldsCompatible sequential fields may share a time axis, using field_name(time). Alternatively, partitioning by FIELD_ID yields separate datasets. A mosaic is not required to occupy one hypercube.
Continuum and line SPWsDifferent spectral contexts generally occupy different partitions. Batches have compatible spectral coordinates and correlation setup; the algorithm may combine several batches scientifically.
Large metadataMoving-source, pointing, and ephemeris metadata are queried in bounded windows instead of loading sample-sized histories on open.

Why a mosaic need not add a visibility axis

In a sequential mosaic, the correlated field is a function of time. The visibility array has axes [time, baseline, frequency, polarization], while an auxiliary coordinate labels each time:

TimeField coordinateVisibility slice
t0AV[t0, :, :, :] belongs to field A
t1AV[t1, :, :, :] belongs to field A
t2BV[t2, :, :, :] belongs to field B
t3AV[t3, :, :, :] is a later visit to A

There is no independent A-versus-B choice at t0 in this example, so a time × field visibility grid would introduce unused combinations. The fields are neither averaged nor overlaid. The reader preserves the field association, and imaging applies the appropriate geometry to each sample.

XRADIO can also split by field. Its default extra partition scheme is empty, explicitly recommended for rapidly changing phase centres in on-the-fly mosaics; required spectral/observation partitioning still applies. Antenna beam-pointing history is separately indexed by time and antenna in pointing_xds. Simultaneous beams or phase centres need an explicit supported mapping; this sequential example does not settle those cases.

Verified against the pinned field_name(time) schema, partitioning options, and antenna pointing schema.

What the actual MSv2 → MSv4 converter does

XRADIO's convert_msv2_to_processing_set reads the original field IDs, constructs one field label per time, and attaches field_name(time) to the visibility dataset. Repeated visits produce repeated labels. The field/source dataset supplies the associated phase centres; ephemeris fields also carry time-dependent information.

The upstream VLA SNR_G55 test exercises both combined-field and field-partitioned conversion. The ALMA solar-mosaic test uses combined fields and requires one dataset after selecting its target SPW/line/intent. The VLASS test also uses combined fields, explicitly avoiding the many partitions generated by splitting on field.

An assumption our adapter must check: the converter takes the maximum field ID across baselines at each time. This gives the right label when all present baselines agree; it does not check agreement. Our proposed conversion must validate this, partition compatibly or reject conflicting fields. Distinct acquisitions must never overwrite one another to fit the array.

Evidence is from inspection of the pinned converter and upstream tests. Those conversions have not been run for this proposal; their aggregate/schema checks do not by themselves prove every input field association survives.

Identity needs care when calibration is saved and reopened

Catalogue handles belong to an opened observation. They are not permanent MS row numbers. Calibration owns the binding to antenna/SPW/field identities in a persisted caltable. Reopening and changing catalogue enumeration must not change which solutions apply.

04 · The central intermediate structure

A batch is arrays plus their meaning.

A VisibilityBatch exposes the actual visibility, flag, weight and coordinate buffers used for computation. The source has read and decoded the requested payload before delivering the batch; accessing an element does not trigger storage I/O.

A concrete batch: two samples, two channels, four correlations

This illustrative batch has one time and two ordered baselines. Sample 0 is antenna 0 with itself; sample 1 is antenna 0 with antenna 1. Both use feed 0. The correlation order is [XX, XY, YX, YY]. These are invented numbers for explanation, not a converted observation.

time: MJD 60000 TAI + 0 s (split epoch)
frequency_hz: [1_000_000_000, 1_001_000_000]  // TOPO
field: A; phase centre: (1.0, 0.5) rad, ICRS
uvw_m: [[0, 0, 0], [100, -40, 20]]          // per sample
// UVW refers to this phase centre and the declared baseline convention.

groups[0].values is a borrowed view of 16 complex numbers: Complex<f32>, in Jy, shape [sample=2, channel=2, correlation=4]. Each number has an f32 real part and an f32 imaginary part, so this payload occupies 128 bytes.

Contiguous element strides: [8, 4, 1]. Flat visibility/flag index = 1×8 + 0×4 + 0 = 8. Native weight index = 1×4 + 0 = 4.

The batch lends these buffers for its lifetime. A numerical loop reads typed array elements directly; no catalogue lookup or per-value type dispatch is needed. Other requested data groups expose their own associated arrays. A flags-only request can omit visibility values entirely.

Where those buffers sit in the structure

Typed visibility values

In the example, groups[0].values lends the 16 Complex<f32> numbers above with shape [2, 2, 4] and element strides [8, 4, 1]. Select the typed loop once per batch.

}

Requested roles only. A flags-only operation need not read visibility values. Missing required roles fail binding.

Metadata declares which axes it depends on. A constant frequency frame, per-time epoch, or per-correlation row weight should not become one allocated object per visibility.

The coordinates are native casa-rs Measures

The batch exposes Measures' own frequency, direction, epoch, position and reference types. The frequency numbers above belong to a native Measures array view carrying FrequencyRef::TOPO; the epoch uses EpochRef::TAI and split precision. Measures conversion functions accept those views directly. There is no second set of “MS measures” to translate before computation.

We will extend or rework casa-types::measures and quanta to support this naturally. Array views share reference metadata and borrow numeric buffers; they do not require one full measure/frame object per value. MSv2/MSv4 metadata is decoded into those types at the I/O boundary, with the original encoding retained where needed for faithful writes.

Bulk conversion throughout Measures

This applies to directions, epochs/time scales, positions, baselines/UVW, frequencies, radial velocities, Doppler conventions, magnetic vectors, unit conversions, and future measure families. LSRK↔TOPO is one example.

Bind the routeSource/destination references, units, scientific policy and provider
→
Prepare the contextShared model/context work → family-specific factors, matrices or other prepared state
→
Convert the sliceTyped scalar/vector arithmetic, including necessary nonlinear work, into reusable output storage

Examples: 4096 frequencies can share prepared Doppler factors; many directions at one epoch/site can share frame preparation while retaining per-direction corrections. An epoch array crossing a leap second cannot assume one offset. These illustrate the work pattern, not measured speedups.

What can be reused, and how workers share it

Hoist invariant route, frame and model work; avoid repeated invariant provider lookups and per-value allocation/locking. Preserve genuinely value-dependent mathematics and prepare varying auxiliary inputs in bounded groups. Direction, geodetic, time-scale and Doppler transformations can be nonlinear or piecewise; the common bulk contract does not assume a single matrix, offset or scale for every array.

Source and destination contexts can differ, such as when mapping an observation to a fixed image reference epoch. Changing an epoch, direction, observer or scientific model can require new prepared state. Prepared transforms are immutable and shareable. Mutable conversion state and output buffers belong to admitted work units. Existing CASA-compatible interpolation depends on preparation order: retain that sequence across batches, then let workers finish applying prepared transforms independently. Bound retained context state and queues.

Current code already has an ordered MFrequencyConverter, a reusable UvwFrame, and prepared frequency factors inside casa-ms. Consolidate these in Measures. M1 must exercise every currently supported family, compare its scientific results and performance against appropriate existing paths, and include real spectral and non-spectral consumers. Frequency plus one other example is insufficient. Converting coordinates does not itself regrid the visibility values.

Read: native Measures and bulk-conversion contract, M1 Measures trial, and pinned existing Measures source map.

Should autocorrelations be real?

The same-receptor power products are real in the ideal measurement: XX = ⟨Eₓ Eₓ*⟩ = ⟨|Eₓ|²⟩, and similarly YY (or RR/LL), for the same antenna and feed. But XY = ⟨Eₓ Eᵧ*⟩ can be complex, with YX = conjugate(XY) ideally. The example's auto row therefore has real XX/YY and complex XY/YX.

MSv2 DATA and MSv4 VISIBILITY use complex arrays, so auto and cross baselines can share one array and one typed loop. MSv2 also has real FLOAT_DATA; MSv4 has a separate real SPECTRUM array for single-dish data. The batch preserves the supplied scalar type and values. Antenna equality alone cannot authorize discarding imaginary parts or changing dtype.

Storage type, physical meaning, and the initial support scope

The ideal auto correlation matrix is Hermitian; different feeds/signals or stored processing results require their own interpretation. Reading does not force supplied data to satisfy ideal reality or conjugate symmetry. Selecting only real self-products from a complex array could support an explicitly requested real projection, but its imaginary-value handling and write semantics would need a defined policy.

The shared real-valued variants cover supported legacy FLOAT_DATA. XRADIO SpectrumXds uses [time, antenna, frequency, polarization] and remains outside the initial MSv4 VisibilityXds profile. This explanation does not expand that implementation scope.

Sources: MSv2 DATA/FLOAT_DATA definitions, MSv4 complex VISIBILITY, and real SPECTRUM.

Known units at the numerical boundary

The proposed default views guarantee Hz for frequency, m for distances, rad for angles, and s for durations. Epochs retain explicit origin/representation, time scale, and split precision. A caller can request another compatible unit at binding; the result guarantees that choice. A frequency_hz() accessor cannot return MHz.

Canonical units, explicit conversions, and the MSv4 convention

Unit syntax and scaling are resolved once at the appropriate metadata scope. Shared axes are converted once where possible; other scaling can be fused with fill/decode/packing. Already-canonical views need no unit-conversion pass. Frames remain separate: Hz in TOPO is not Hz in LSRK, and seconds do not imply UTC or TAI.

The pinned MSv4 schema constrains the main coordinate quantities to Hz, m, s and rad. Visibility units are a string defaulting to Jy. We propose Jy for established flux-density data, rather than converting everything to SI base units; instrumental data cannot acquire a flux calibration through unit conversion. Declared inverse-variance weights and matching sigma must scale consistently with amplitude units.

Computation does not rewrite persistent unit metadata. Updates convert back to the destination's units under scope and precision checks.

Sources: coordinate units, visibility units, and proposed unit contract.

Three facts stay separate: selection, whether an acquisition is known to exist, and whether its requested values are usable. NaN padding or a false flag does not prove an acquisition occurred.
Precision is an explicit request

Native precision, lossless widening, and approved narrowing are different policies. The initial imaging binding requests complex64 input (Complex<f32>); narrowing complex128 requires scientific approval. Grid precision does not authorize input conversion.

05 · Topology and element order

Keep the measurements.
Change how the kernel sees them.

The initial contract offers sample-major and channel-major views. Either can retain factored time/baseline coordinates.

[sample, channel, correlation]

Read each displayed row left to right: the channels for one sample are adjacent; correlations are innermost.

Toy array: 2 times × 3 baselines = 6 samples, 4 channels, 2 correlations. Each cell represents both correlations. This shows element order, not a measured transpose cost.

Irregular topology

A list of acquisitions, each with a channel × correlation array. Missing baselines, repeated time/baseline coordinates, and variable row shapes need explicit handling.

Time–baseline topology

Separate time and baseline axes plus occupancy. Compatible contiguous MSv4 data can use sample = time × B + baseline without copying values.

Checked strides determine whether a view is possible. Transposes, sparse gathers, type conversion, and decompression can require accounted buffers. The interface does not promise universal zero-copy access.

What factoring saves, and what it cannot save

Time and baseline coordinate entries can scale as O(T+B). UVW and other truly sample-dependent data still scale with the samples. A rectangular view has one slot per time/baseline pair; duplicate acquisitions cannot be silently averaged or overwritten to make them fit.

06 · Algorithm-led access

The algorithm states its needs.
The adapter binds a realization.

The processing planner sends the adapter a declared access pattern plus required units, precision, and layouts. The adapter returns a realization within the admitted memory and worker budget.

Example request

Selected channel wave; visibility, flags, weights, UVW and frequency context; a kernel-compatible channel-local layout.

Binding must disclose

Actual chunks decoded, packing and image-state memory, and repeated whole-band reads if stored chunks span more channels than the wave.

Illustrative requests, not universal defaults. The processing planner supplies the operation's requirements before iteration; the numerical loop receives the agreed views.

Hard requirementPreferenceBinding result

The budget includes payloads, decoded chunks, codec scratch, packed copies, indexes, caches, queued writes, and consumer state that are alive together. A backend cannot make a minimum decode buffer disappear by promising smaller compute windows.

Chunk geometry still matters. Reading a narrow channel window from a full-band compressed chunk may decode the full band repeatedly. Larger aggregation alone does not fix this; creation policies and admitted traversal choices must be measured.

07 · Scientific completion

A solution interval can span many batches.

A splittable solver consumes fragments and retains its admitted accumulator state. The storage batch does not set the solution boundary.

Two interleaved scientific groups, K0 and K1

Each can be a solution-bin/SPW key under an explicit grouping rule. A combined-SPW solve uses a different declared key. This sequence illustrates control events, not a solver implementation.

  1. 1 · K0 First → job A
  2. 2 · K1 Whole → job B
  3. 3 · B finishes
  4. 4 · K0 Last → job C
  5. 5 · C finishes
  6. 6 · A finishes
0 of 6 events

K0

No fragments received.

K1

No fragments received.

“Whole” and “Last” prove no more input is coming for that group. Finalization also waits for all jobs consuming its fragments.

The algorithm may accept sequential groups or a bounded set of concurrent groups. Concurrent fragments can preserve storage locality, but admission includes every live accumulator, statistics buffer, and group index.

Closing a group needs a proven traversal frontier or end-of-stream. Seeing a later timestamp in an unordered stream is insufficient. A later GroupEnd can close input when the final payload could not carry that proof; completion is signaled exactly once.

What if a solve needs every sample at once?

It must declare that requirement. It either fits within admission, uses an explicitly supported equivalent bounded strategy, or fails. Storage does not secretly build a whole-observation replay cache. Iterative revisits are explicit bounded passes.

Fast work can retire while slow work continues.

Ownership follows a work unit. It can have one worker or cooperating workers, private scratch, and borrowed read-only input.

Illustrative input-buffer sizes and durations, not benchmark results. Scratch, image state, and codecs are additional costs. Grey capacity is reusable, not necessarily returned to the OS.

Independent jobs can finish out of order where the algorithm permits. Shared mutable arrays require exclusive ownership or proven disjoint regions. Buffers are reused only after actual last use, including any outstanding device operation. Queues and scratch stay under the existing resource authority.

Your cube CLEAN example

Visibility batches belong to gridding/prediction passes. Model, residual, mask, and solver state belong to imaging. A channel needing more minor-cycle iterations should not keep its input visibility batch alive. A completed channel can release scratch and free workers for other admitted work; required image state survives for later major cycles and products.

Scientific coupling and major-cycle/stopping rules may still require joins. The shared representation itself adds no global “all channels must finish” barrier.

09 · Addressed mutation

Reordering must preserve where updates belong.

A read can carry a session-scoped, role-specific inverse map. The consumer submits a bulk patch; the adapter resolves it to actual cells, scalars, chunks, or shards.

Source elements[A, B, C, D]
→
Selected / reordered[C, A] + inverse map
→
Patch values[C′, A′]
→
Updated source[A′, B, C′, D]

Letters denote logical elements. Physical addresses remain inside the adapter. Averaging C and A loses this simple inverse and needs an explicit output/scientific scatter rule.

Write scope can be larger than a visible slice

Suppose one native WEIGHT = 2 supplies two channels. Setting only channel 0 to 8 cannot silently change that scalar, because channel 1 would change too. The request must authorize the wider scope, create and initialize a supported channel-resolved destination, or be rejected.

The same care applies to data groups sharing variables and integer flags carrying multiple reasons. Updates preserve unselected values and unknown flag bits. The sink coalesces physical writes within bounded flush windows.

Locks and failures are part of the contract

Plan read/write ownership before traversal, including destination-column creation. Original-input semantics need disjoint native regions or a proven read-before-write order. MSv2 retains ordinary casacore locks and partial-failure behavior.

The proposed local MSv4 profile replaces each encoded object atomically on supported filesystems. Failure may still leave some objects updated and others unchanged. This does not provide a dataset transaction, concurrent-reader snapshot, cross-process XRADIO lock protocol, or an automatic power-loss guarantee.

Production orchestration and science are Rust. Native codec dependencies are compatible with this goal; optional Python tooling can prepare data and serve as an interoperability oracle.

Existing MSv2 performance and interoperability must survive. MSv4 must show a useful larger-aggregation benefit on matched workloads, including wall time as well as operation counts. Memory includes all retained allocations; a four-worker gain cannot conceal a single-worker regression.

Competent implementation agents receive bounded packets with reviewed contracts, fixture recipes, and exact checks. A stronger independent reviewer evaluates milestone evidence. Missing prerequisites keep a gate blocked.
