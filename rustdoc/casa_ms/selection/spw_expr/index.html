CASA’s MeasurementSet spectral-window and channel selection: the spw expressions of casacore’s MSSelection, ported from MSSpwGram.ll, MSSpwGram.yy, MSSpwParse.cc and MSSpwIndex.cc at casacore aaf72eb7, the commit CASA 6.7.6.14 builds.

resolve_spw_selector resolves an expression against the SPECTRAL_WINDOW rows (SpectralWindowRow) and the DATA_DESCRIPTION rows (DataDescriptionRow) into a SpwSelection holding what MSSelection reports for it: the windows (getSpwList), their data descriptions (getSPWDDIDList), the channel list (getChanList, from which getChanFreqList and getChanSlices follow) and the data descriptions whose MAIN rows the selection keeps. MeasurementSet::resolve_spw_selector reads those rows from a MeasurementSet.

§Forms

§Refusals

Besides syntax errors and reversed ranges, CASA refuses an expression when any window term matches nothing (a name, pattern, >/</<> bound, or index naming no row): the “no match” reports go to the MSSelectionErrorHandler, which throws once parsing ends (MSSelection.cc:859-883). A frequency that matches no window throws at once (MSSpwIndex.cc:298-307). Without any window that has an unflagged data description, or without any channel range, the expression is refused (MSSpwParse.cc:307-312, MSSpwGram.cc:121-123).

§CASA quirks this port keeps

  • An index past the last row is looked up as a NAME: in a 10-window MeasurementSet whose window 4 is named 12, 12 selects window 4, while 7 is always window 7 (MSSpwIndex.cc:82-98).
  • A window’s FLAG_ROW, and a data description’s, remove the window from spw_ids and its rows, but not its channels from channel_list; a window without a data description likewise (MSSpwParse.cc:106-148). A window with two data descriptions is listed twice.
  • spw_ids, its data descriptions and the channel list keep the expression’s order and repeats.
  • A channel range in hertz reads the channel order from the sign of the first CHAN_WIDTH, not from the frequencies, and divides its step by the largest signed width; one frequency selects the channels on either side of it.
  • A single window frequency compares with the largest signed CHAN_WIDTH, so it matches no window with negative widths.
  • When a window’s first channel range in hertz finds no channel, the next window takes its ranges from that window’s second range on (MSSpwParse.cc:238-250); ranges after the first may keep a start of -1.
  • In a window list, a frequency replaces the list built so far but not the write position, so an index after it overwrites from there and pads with zeros (window 0): 100GHz~101GHz;0 lists the matched windows and then 0 again (MSSpwIndex.cc:641-688).
  • ( ... ) skips the step that turns the windows into a row condition, so the selection keeps every MAIN row (SpwSelection::rows_restricted is false) while still listing the windows and channels.
  • Scanning follows flex: "text or /text without its closing quote ends the expression (0"x is 0); a backslash or newline inside quotes is dropped; a byte from 0x80 up ends the expression (0é is 0); - is no name character, so LBAND-A must be quoted; e5 and +2 are numbers; Hz and MHz are units, not names.
  • Out-of-range channels are logged, as CASA logs them, in SpwSelection::warnings.

§Not ported

  • A number sscanf("%f") cannot read (., +, e5), which CASA reads as an uninitialised Float, and an index outside a C Int, whose cast is undefined (x86 and ARM differ), are refused.
  • A stepped frequency search that CASA never leaves (a negative step on a window whose least CHAN_WIDTH is negative, or a step too small to move a single-precision frequency) is refused rather than run forever; one longer than 2^27 steps is refused too.
  • A window list mixing frequencies and indices that CASA would write past its end is refused.
  • Messages follow CASA’s wording but not its character positions, and a syntax error may be reported where CASA reports a name it looked up before reaching it.
