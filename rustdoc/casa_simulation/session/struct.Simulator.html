pub fn set_apply(&mut self, spec: &ApplySpec) -> SimulatorResult<()>

sm.setapply(...): corrupt by the calibration table spec.table at each later corrupt, its solutions taken at each integration observed by then.

§Errors
  • The table cannot be read, its type is not the type asked for, or interp is CASA’s deprecated aipslin: raised, as CASA raises.
  • A table of other than G or D solutions; calwt, a nonzero t or opacity, or an interpolation other than linear or nearest: not yet implemented. (A table without a solution, or with a flagged one, for an antenna and integration is refused at corrupt.)
  • No rows observed yet: refused, as setgain refuses.

pub fn set_noise(&mut self, spec: &NoiseSpec) -> SimulatorResult<()>

sm.setnoise(...): add a noise term with the current seed.

§Errors
  • A mode CASA does not know: CASA logs “unsupported mode … in setnoise()” and returns False.
  • OTF=False: not yet implemented; nor is a Tsys mode with a table, which CASA writes.
  • No rows observed yet: CASA cannot size the term on an empty MeasurementSet and returns False, adding no term.
  • A Tsys mode with a water vapour above 100 mm, or a zenith Tsys at the centre of the first spectral window that is not positive or is above 10⁶ K: CASA returns False. It has added a unit-σ noise term by then, which casa-rs does not (docs/CASA (C++) bugs.md). casa-rs also refuses a tsys-atm zenith Tsys that is not a number, which CASA’s check lets through.
  • tsys-atm with site values ATM cannot build an atmosphere from, or whose atmosphere the session’s memory budget cannot hold.
Source

pub fn corrupt(&mut self) -> SimulatorResult<()>

sm.corrupt(): apply every term to the rows observed so far: the gains and leakages (setgain, setleakage), then the noise. With no terms it does nothing.

§Errors
  • A scan observed so far with a correlation count other than 1, 2 or 4, which CASA cannot corrupt (“No such VisVector type”); leakage on a scan without all four correlations (CASA’s JonesGenLin raises); or a noise term applied 2²⁴ times.
  • A scan in a spectral window a gain or leakage term has no solution for, which CASA leaves uncorrupted, or one defined after a tsys-atm term was set: not yet implemented.
Source

pub fn reset(&mut self)

sm.reset(): remove every noise, gain and leakage term. Corruptions already applied, and the seed, stay.

pub fn set_gain(&mut self, spec: &GainSpec) -> SimulatorResult<()>

sm.setgain(...): simulate antenna gains over the rows observed so far and add them to the terms corrupt applies.

§Errors
  • mode='table': CASA logs “Cannot yet read from table” and returns False; another unknown mode is refused as CASA’s “unsupported mode”.
  • No rows observed yet, or no amplitude: refused.
  • A table path that cannot be made absolute, or that is, lies inside or contains the session’s MeasurementSet: raised.
  • The term’s memory does not fit the session’s resource policy: an admission error, before anything is formed.

pub fn predict(&mut self, spec: &PredictSpec) -> SimulatorResult<()>

sm.predict(imagename, complist, incremental): predict the model into the rows observed so far, replacing their DATA or, when incremental, adding to it.

§Errors
  • Raised, as casatools’ binding raises before predicting: a named image that does not exist or does not open (PredictSpec::check_images).
  • Not yet implemented: more than one image, a model layout CASA reads and casa-rs does not (other than Stokes I, J2000, direction–Stokes–spectral axes), a component casa-rs does not predict (a direction not in J2000, or a flux, spectrum or shape casa-components does not evaluate), a near-field distance on the last field, scans whose windows differ in correlations, or setvp(dovp=True) for a telescope whose default pattern casa-rs does not have (ALMA’s, ACA’s, the VLA’s and the EVLA’s it has) or for pointings observemany moved off their fields.
  • CASA’s False: no model image (“No model images found”), or no rows observed yet.
  • Raised: a scan of 3 correlations (“No such VisVector type”), or model grids or kernels, or a component list’s read or preparation, that do not fit the session’s memory budget (SimulatorError::admission_refused).
  • As the FTMachine setoptions chose refuses: WProjectFT with fewer than two planes, or on the Metal backend.

pub fn set_trop(&mut self, spec: &TroposphereSpec) -> SimulatorResult<()>

sm.settrop(...): simulate the troposphere’s phase over the rows observed so far and add it to the terms corrupt applies.

§Errors
  • An unknown mode is refused as CASA’s “unsupported mode”; mode='test' is not yet implemented.
  • No rows observed yet; a pwv that is not positive; integrations spanning less than one slot (CASA’s setEvenSlots “logic problem”): refused.
  • What CASA’s checks let through into undefined phases: an argument that is not a finite number in single precision; in individual mode, integrations spanning fewer than six slots, on which a series is flat; in screen mode, a negative windspeed, a dish of no size, or a screen too large to make: refused.
  • A table path that cannot be made absolute, or that is, lies inside or contains the session’s MeasurementSet: raised.
  • The term’s memory does not fit the session’s resource policy: an admission error, before anything is formed.

pub fn set_mosaic_field( &mut self, name: &str, calcode: &str, centre: &MDirection, (nx, ny): (usize, usize), spacing_rad: f64, distance_m: f64, ) -> SimulatorResult<()>

sm.setmosaicfield(sourcename, calcode, fieldcenter, xmosp, ymosp, mosspacing, distance): add an nx × ny grid of fields, named {name}_{k} with k counting down each column (y fastest) and then across, spacing_rad apart in latitude and in longitude at the centre’s latitude, centred on centre and in its frame.

Divergence (plan §4, docs/CASA (C++) bugs.md).

  • CASA tests an odd count as nx/2 != floor(nx/2) in integer arithmetic, so every grid takes its even-count offsets. Those count from zero where one was meant, so CASA’s grids sit off their centre.
  • Over a pole, CASA sets the longitude to |π − α|, where crossing the pole moves it by π.

casa-rs centres each grid on centre: offsets (i − (n − 1)/2) times the spacing. It crosses a pole as the sphere does.

§Errors

As set_field, for any of the fields.

pub fn set_data( &mut self, spectral_window_ids: &[i64], field_ids: &[i64], ms_select: &str, ) -> SimulatorResult<()>

sm.setdata(spwid, fieldid, msselect): select the rows the next predict and corrupt act on, until the next observe, which drops CASA’s selection.

CASA’s selection works on the rows observed so far:

  • their FIELD_ID must be among field_ids, when there are any;
  • their DATA_DESC_ID must be one of the windows spectral_window_ids names, when it names any (casa-rs’s data description w is window w);
  • then the TaQL msselect applies;
  • a selection that keeps no row reverts to every row, with a warning.

casa-rs takes a selection that keeps every row, as simobserve’s setdata(fieldid=range(nfld)) does. The following steps then act on every row observed so far, as without setdata.

§Errors

Not yet implemented: a selection that keeps some but not all of the rows, or a non-blank msselect.

pub fn close(self) -> SimulatorResult<()>

sm.close() / sm.done(): write the MeasurementSet, or, after openfromms, patch the rows the DATA steps rewrite in place; then write the calibration tables setgain and setleakage named.

§Errors

A failure to create, read or write the MeasurementSet or a calibration table.
