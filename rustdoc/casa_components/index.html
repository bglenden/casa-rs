CASA component lists: parameterised models of the sky brightness, and the casacore tables CASA keeps them in.

A component list is an ordered list of sky components. Each component has a flux, a shape that places it on the sky and spreads it, a spectral model that scales it with frequency, a label, and optional parameters. This crate models them as CASA’s components module (ComponentModels/ in casatools) does, with Rust enums in place of its class hierarchies:

casa-rsCASA
ComponentListComponentList
SkyComponentSkyComponent / SkyCompRep
Flux with PolarisationFlux<Double> / FluxRep with ComponentType::Polarisation

SpectralModel with SpectralKindSpectralModel: ConstantSpectrum, SpectralIndex, TabularSpectrum, PowerLogPoly

Directions and frequencies are casa-types measures (MDirection, MFrequency) carrying their frames, and errors that carry units are casa-types Quantity values.

ComponentList::read_table reads a table as CASA’s ComponentList::readTable does, and ComponentList::write_table writes one as its createTable and writeTable do, so CASA reads it back unchanged.

§The table format

A component list is a casacore table with one row per component. Its table description is named ComponentListDescription, version 4, with the comment “A description of a component list”; its table info has type Component List, no subtype, and two readme lines. Every column is in one StandardStMan except Optional_Parameters.

(A Direct column also carries casacore’s FixedShape option.) The keywords are casacore’s measure and quantum descriptions:

  • Reference_Direction: QuantumUnits = ["rad", "rad"] and MEASINFO = {type: "direction", VarRefCol: "Direction_Frame"};
  • Reference_Frequency: QuantumUnits = ["Hz"] and MEASINFO = {type: "frequency", VarRefCol: "Frequency_Frame"};
  • Direction_Error: VariableUnits = "Direction_Error_Units";
  • Frequency_Error: VariableUnits = "Frequency_Error_Units".

Optional_Parameters exists only in lists holding a limb-darkened disk. Lists written before CASA added them lack the error columns and Spectral_Record; such lists read with zero errors and with each spectral model’s defaults for what only the record holds.

§Visibilities

SkyComponent::visibility forms a component’s visibility as CASA’s SkyCompRep::visibility does: the Stokes flux sampled by the spectral model (SpectralModel::sample_stokes), converted to the data’s polarisation basis (stokes_in), times the shape’s visibility (ComponentShape::visibility_scale). A limb-darkened disk’s visibility and some tabular spectra are refused (the visibility module lists them). A predictor evaluating many baselines and channels prepares each shape’s ShapeTransform once, takes it at each baseline (ShapeTransform::at_baseline) and leaves each channel a function of frequency alone (BaselineTransform::at_frequency).

§Records

ComponentList::to_record and SkyComponent::to_record form the records CASA’s toRecord does, which the cl tool’s torecord and getcomponent return; the flux, shape and spectrum each have their own (Flux::to_record, ComponentShape::to_record, SpectralModel::to_record).

§Deliberately not here

  • Sampling components on an image.
  • The cl tool itself: its argument conventions, its selection state and when it writes its table belong to casars.tools.componentlist. Reading records back (fromrecord) is not here either.
  • Display units: CASA remembers the units each shape axis was given in; tables do not store them, and casa-rs keeps radians. Records give a shape’s axes in the units CASA gives one read from a table.
  • Table keywords: a list’s table keywords (cl.putkeyword) are not read or written.
