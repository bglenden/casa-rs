Expand description

One partition: a store unit and the content that defines it.

The content keys (spectral window, correlation products, intents, observation, feed pair) and the fields and scans the partition’s samples visit are what two stores of one observation agree on; the MSv2 adapter partitions rows the way XRADIO’s converter does by default (DATA_DESC_ID × OBS_MODE × OBSERVATION_ID × EPHEMERIS_ID, and the feed pair, which MSv4 has no axis for), so the same observation opens as the same partition set from either store. Cross-store matching (Catalogue::bind_to) compares content, never list positions.

Fields§

§spectral_window: String

The spectral window’s name as stored.

§frequencies_hz: Vec<f64>

Channel centres in hertz.

§frequency_frame: FrequencyRef

Their spectral frame.

§channel_widths_hz: Vec<f64>

Signed channel widths in hertz.

§correlations: Vec<Correlation>

The correlation products, in stored order.

§intents: Vec<String>

The scan intents of every sample (MSv2 STATE::OBS_MODE, MSv4 scan_name.scan_intents), sorted.

§observation: ObservationId

The observing session.

§feeds: Option<[u32; 2]>

The feed pair (MSv2 FEED1, FEED2) of every sample; None for a store without a feed axis (MSv4).

§fields: Vec<FieldId>

The fields the partition’s samples are phased to, over every data group, sorted.

§scans: Vec<ScanId>

The scans its samples belong to, sorted; empty for a store that names none (an MSv4 dataset without scan_name).

§baselines: Vec<OrderedBaseline>

The baseline table: sample t × baselines.len() + b of every batch is baseline b.

§time_scale: EpochRef

Time scale of the partition’s times and time centroids.

§time_origin: MjdHighPrec

Origin the partition’s time offsets count from (MJD 0 for MSv2, the Unix epoch for MSv4 format: unix).

§data_groups: Vec<DataGroupEntry>

The partition’s data groups.

pub fn same_content(&self, other: &Self) -> bool

Whether other has the same spectral and product content: the same channel frequencies and widths (bit for bit) in the same frame, the same correlation products in the same order and the same intents. Names, which converters rewrite, take no part; the keys that name other entities (observation, fields, scans) and the feed pair are compared by Catalogue::bind_to through the binding.
