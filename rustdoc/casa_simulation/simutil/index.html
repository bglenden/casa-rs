CASA’s simutil helpers that simobserve uses (simulation Phase 5, #841): CASA 6.7.6’s casatasks/src/private/simutil.py, ported as its specification (ADR-0018).

CASA’s numbers to the last bit. Pointing lists are compared with CASA’s as strings, so the arithmetic follows CASA’s: every qa call goes through casacore’s Quantum arithmetic ([casa_types::quanta::casacore]), which converts units as casacore rounds and names them as casacore names them, and numbers that CASA writes into strings and reads back (str(x)+"arcsec", '%17.12fdeg' % x) are written and read back the same way. The tests compare a grid of CASA’s outputs (tests/data/simutil_casa.json, from tools/simulation/simutil_oracle.py).

Where casa-rs differs. CASA raises Python exceptions where these functions refuse an input; casa-rs returns SimutilError. It also departs from CASA in a few places, each recorded in docs/CASA (C++) bugs.md:

  • calc_pointings2’s ALMA tiling takes its default beam from spacing × pbcoeff × √3, but CASA’s pbcoeff is undefined there (NameError); casa-rs uses simobserve’s 1.13.
  • noisetemp’s receiver lookup reads f0[z] before testing z, so above an unknown telescope’s last tabulated frequency CASA raises IndexError; casa-rs keeps the last temperature. At a frequency equal to the first entry of the table, CASA’s t0[z-1] with z = 0 reads the last temperature (230 K for ALMA at 35 GHz); casa-rs reads the first.
  • direction_splitter reads its second and third fields whatever the field count, so a direction without an epoch raises IndexError in CASA; casa-rs refuses it with a message.

Where CASA has no answer, casa-rs refuses: calc_pointings2 lays out no map of more than pointings::MOST_POINTINGS pointings, where CASA runs for hours or out of memory (a spacing tiny beside the map).
