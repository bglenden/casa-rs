4//! Shared observation contracts for MeasurementSet v2 and MSv4: the
5//! [`VisibilityBatch`] that storage adapters fill and numerical consumers
6//! read, the [`AccessRequest`] consumers estimate and bind, and the
7//! [`Traversal`] of [`VisibilityCursor`]s that delivers batches.
8//!
9//! **Trial status.** This crate is the executable sketch of
10//! `docs/measurement-set/contracts.md` for the MSv2/MSv4 trial
11//! (`docs/measurement-set/trial/README.md`), at its third revision
12//! (`docs/measurement-set/trial/revision-2-design.md`, then the README's
13//! "Revision 3"). Its interfaces are
14//! not frozen.
15//!
16//! # The principle
17//!
18//! MSv4 is the future: the interface takes MSv4's native shape, and the
19//! MSv2 adapter assembles MSv2 data into it once, at opening. A consumer
20//! cannot tell the stores apart from a batch.
21//!
22//! # The pieces
23//!
24//! - An [`Observation`] is the boundary algorithm code sees, whatever
25//!   stores the data: its [`Catalogue`] names the antennas, fields, scans,
26//!   observing sessions and partitions with identities scoped to that
27//!   opening, and holds every per-partition constant once (channel
28//!   frequencies and frame, correlation products, the baseline table, the
29//!   time system, the data groups). Backend choice happens when the
30//!   observation is opened.
31//! - A **partition** is a store unit described by its content: spectral
32//!   window, correlation products, intents, observing session, feed pair.
33//!   The MSv2 adapter partitions rows the way XRADIO's converter does, so
34//!   the same observation opens as the same partition set from either
35//!   store.
36//! - An [`AccessRequest`] says what a traversal must deliver: the
37//!   partition set, data group, roles (payload, time auxiliaries, scan),
38//!   channel window, correlation products and flag policy, scientific
39//!   grouping and the byte budget of one batch. [`Observation::estimate`]
40//!   costs it from the catalogue and the store's geometry alone (the
41//!   **batch shape**: times per batch, bytes, read amplification, natural
42//!   blocks, padding); [`Observation::bind_read`] binds it, refusing a role
43//!   the store lacks, and returns one cursor per partition with the same
44//!   [`Estimate`].
45//! - A [`VisibilityCursor`] fills caller-owned [`BatchBuffers`] through one
46//!   checked path ([`BatchBuffers::begin`], [`BatchFill::finish`]) and lends
47//!   them as a [`VisibilityBatch`], or announces a [`ReadEvent::GroupEnd`].
48//!   Owned batches ([`FilledBatch`]) are filled into a bounded
49//!   [`BufferPool`] and return their buffers when dropped; concurrent work
50//!   on a group is joined by [`GroupCompletion`]'s [`WorkToken`]s.
51//!   Within a cursor the **traversal order** is fixed: whole times of one
52//!   channel window of one partition, in time order; across cursors it is
53//!   the consumer's.
54//! - A batch is whole times of the partition's time × baseline grid:
55//!   sample `t × B + b`, with the field and scan per time, its times,
56//!   frequencies and UVW in native Measures views
57//!   ([`casa_types::measures::EpochView`] and friends), the payload as
58//!   [`ndarray`] views in the **payload order** `[sample, channel,
59//!   correlation]`, and one [`Validity`] rule over its flags, values and
60//!   weights. A grid cell no acquisition filled is padding: flagged in
61//!   every store (the MSv4 adapter folds XRADIO's NaN weight into the
62//!   flag), its values and time auxiliaries NaN.
63//!
64//! # Example
65//!
66//! A consumer binds a request against any observation, then loops over
67//! events; the borrow of the buffers ends before each refill.
68//!
69//! ```
70//! use casa_observation::{AccessRequest, BatchBuffers, Observation, ObservationError, ReadEvent};
71//!
72//! fn total_weight(
73//!     observation: &dyn Observation,
74//!     request: &AccessRequest,
75//! ) -> Result<f64, ObservationError> {
76//!     let mut traversal = observation.bind_read(request)?;
77//!     let mut buffers = BatchBuffers::default();
78//!     let mut total = 0.0;
79//!     while let Some(event) = traversal.next(&mut buffers)? {
80//!         let ReadEvent::Batch(batch) = event else { continue };
81//!         let (Some(weights), validity) = (batch.group.weights, batch.validity()) else {
82//!             continue;
83//!         };
84//!         let [samples, channels, correlations] = batch.shape();
85//!         for sample in 0..samples {
86//!             for channel in 0..channels {
87//!                 for correlation in 0..correlations {
88//!                     if !validity.excluded(sample, channel, correlation) {
89//!                         total += f64::from(weights[[sample, channel, correlation]]);
90//!                     }
91//!                 }
92//!             }
93//!         }
94//!     }
95//!     Ok(total)
96//! }
97//! ```

128/// Why a request could not be bound or a traversal failed.
129#[derive(Debug, thiserror::Error)]
130pub enum ObservationError {
131    /// The request asks for something this source or the trial does not
132    /// implement. Nothing has been read.
133    #[error("unsupported: {what}")]
134    Unsupported {
135        /// What is unsupported.
136        what: &'static str,
137    },
138    /// The request is inconsistent with the observation.
139    #[error("invalid request: {reason}")]
140    InvalidRequest {
141        /// Why.
142        reason: String,
143    },
144    /// The store does not hold what its profile requires.
145    #[error("invalid store: {reason}")]
146    InvalidStore {
147        /// Why.
148        reason: String,
149    },
150    /// A filled array disagrees with the batch's header.
151    #[error("{array} holds {actual} elements; the batch header needs {expected}")]
152    Shape {
153        /// The array.
154        array: &'static str,
155        /// Its length.
156        actual: usize,
157        /// The length the header implies.
158        expected: usize,
159    },
160    /// Every buffer of a [`BufferPool`] stayed in use for the wait limit
161    /// of the handle taking one ([`BufferPool::waiting_at_most`]). Nothing
162    /// was read: asking again continues the traversal where it was.
163    #[error("all {capacity} buffers of the pool stayed in use")]
164    PoolExhausted {
165        /// Buffers in the pool.
166        capacity: usize,
167    },
168    /// A unit of work on `group` ended without finishing its
169    /// [`WorkToken`]: it panicked, failed or was cancelled, so the group
170    /// cannot complete.
171    #[error("work on {group:?} was abandoned")]
172    WorkAbandoned {
173        /// The group.
174        group: GroupKey,
175    },
176    /// A batch's identities, fragments or sizes are inconsistent, or a
177    /// consumer's completion bookkeeping was misused.
178    #[error("invalid batch: {reason}")]
179    InvalidBatch {
180        /// Why.
181        reason: String,
182    },
183    /// The storage layer failed.
184    #[error("storage: {0}")]
185    Storage(#[source] Box<dyn std::error::Error + Send + Sync>),
186}
