2//! Storage adapters behind the shared observation contracts
3//! (`casa-observation`): MeasurementSet v2 here, MSv4 with the `msv4`
4//! feature.
5//!
6//! [`open`] is the one place a store's format is chosen: it returns the
7//! shared [`Observation`] interface, behind which each adapter dispatches
8//! once per bind and once per batch. Algorithm code takes that interface
9//! and imports neither concrete adapter.
10//!
11//! **Trial status.** These adapters implement the cases the MSv2/MSv4
12//! trial's examples need (`docs/measurement-set/trial/README.md`), at the
13//! trial's second revision (`revision-2-design.md`): the MSv2 adapter grids
14//! rows onto time × baseline at opening and partitions them as XRADIO's
15//! converter does, so both adapters deliver the same batches. The
16//! production readers and writers are unchanged.

33/// When a cursor announces that a scientific group's input is complete.
34///
35/// A source chooses; consumers handle both. The choice is an opening
36/// option only so that tests can exercise the deferred path that a source
37/// without lookahead (interleaved partitions, streaming input) must take.
38#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
39pub enum GroupClosure {
40    /// Mark the closing fragment `Last` or `Whole` whenever the traversal
41    /// can already prove it at delivery.
42    #[default]
43    AtDelivery,
44    /// Never mark fragments closing; send `ReadEvent::GroupEnd` once the
45    /// traversal has read past the group. A test mechanism.
46    Deferred,
47}

49/// How the MSv2 adapter divides MAIN rows into partitions, beyond the keys
50/// every partition has: data description, intents (`STATE::OBS_MODE`),
51/// observation, ephemeris and feed pair (XRADIO's mandatory
52/// `partition_scheme`, plus the feed pair MSv4 has no axis for). An MSv4
53/// store is already partitioned and ignores this.
54#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
55pub struct PartitionScheme {
56    /// Also split by `FIELD_ID`, as XRADIO's `partition_scheme=["FIELD_ID"]`.
57    pub fields: bool,
58    /// Also split by `SCAN_NUMBER`.
59    pub scans: bool,
60}

62/// Options fixed when a store is opened, outside any algorithm.
63#[derive(Clone, Debug, Default, PartialEq, Eq)]
64pub struct OpenOptions {
65    /// How group completion is announced; see [`GroupClosure`].
66    pub group_closure: GroupClosure,
67    /// How an MSv2 is partitioned; see [`PartitionScheme`].
68    pub partition_scheme: PartitionScheme,
69}

71/// Open the observation at `path`, choosing its adapter from the store:
72/// a Zarr processing set (a `zarr.json` at its root) is MSv4, a casacore
73/// table directory is MSv2.
74///
75/// # Errors
76///
77/// When the store cannot be opened by its adapter, or is MSv4 and the
78/// `msv4` feature is off.
79#[cfg(unix)]
80pub fn open(
81    path: impl AsRef<Path>,
82    options: &OpenOptions,
83) -> Result<Box<dyn Observation>, ObservationError> {
84    let path = path.as_ref();
85    if path.join("zarr.json").is_file() {
86        #[cfg(feature = "msv4")]
87        return Ok(Box::new(Msv4Observation::open_with(path, options)?));
88        #[cfg(not(feature = "msv4"))]
89        return Err(ObservationError::Unsupported {
90            what: "an MSv4 store without casa-ms's msv4 feature",
91        });
92    }
93    Ok(Box::new(Msv2Observation::open_with(path, options)?))
94}

96/// The distinct `values`, sorted: a partition's fields or scans from its
97/// per-time identities.
98fn distinct<T: Ord + Copy>(values: &[T]) -> Vec<T> {
99    let mut distinct = values.to_vec();
100    distinct.sort_unstable();
101    distinct.dedup();
102    distinct
