Module scratch_columns

What CASA clears from a MeasurementSet before it writes a scratch column, so that the column casa-rs writes is the one CASA reads (CASA 6.7.5).

  • Cached sort keywords. CASA’s iterators may cache a pre-sorted reference table of MAIN and record it in MAIN’s keywords as SORTED_TABLE, with the columns it is sorted by as SORT_COLUMNS (MSIter2). A sorted table made before a column was added does not see it, so adding MODEL_DATA or CORRECTED_DATA removes both keywords (VisSetUtil::addScrCols; the table itself is left, as CASA leaves it). The MS definition’s own SORTED_TABLES is untouched.
  • The virtual model. CASA can hold a field’s model as a recipe instead of a column: setjy (usescratch=False) and tclean (savemodel='virtual') write one, and CASA’s iterator prefers it to MODEL_DATA (VisibilityIteratorImpl2::visibilityModel). A task that writes MODEL_DATA makes the column “the exclusive origin for model visibilities”, whether or not it adds it: it clears every field’s virtual model first. addScrCols does so when it adds the column (remOTFModel, VisModelData::clearModel of synthesis/TransformMachines/VisModelData.cc), and the imagers do so whenever they write it (SynthesisImagerVi2::selectData, Imager::setjy and ft, refim::VisModelData::clearModel of TransformMachines2). The two clearModel bodies are the same.

A field’s virtual model is a keyword definedmodel_field_<id> naming a model key, in SOURCE’s keywords when SOURCE has rows and MAIN’s otherwise. Under SOURCE the model key is a keyword holding the SOURCE row whose SOURCE_MODEL cell holds the model record; under MAIN it is a keyword holding the record itself. Clearing a field removes both keywords wherever they are and empties the SOURCE_MODEL cell, which is what CASA leaves (measured with setjy then delmod on CASA 6.7.5). A pointer under SOURCE naming a key held in MAIN is removed with the key, where CASA keeps the pointer; either way the field has no model.

clearModel also deletes the model images a gridder’s record names (ft_<k>.container.diskimage), wherever they lie, and every FT_MODEL* table in the MeasurementSet and its SOURCE, where tclean writes them. casa-rs deletes only the FT_MODEL* tables, so that a path in a record never deletes anything else. A multi-MS is cleared as one table, not part by part as CASA clears it.

Functions§

prepare_write
Clear what CASA clears before it writes scratch column column (MODEL_DATA or CORRECTED_DATA) to ms, adding it when adds: for an added column the cached sort keywords, and for MODEL_DATA, added or not, every field’s virtual model, as the module states. Every path that adds either column to an existing MeasurementSet, or writes MODEL_DATA, calls it before it changes the column.
prepare_write_holding
prepare_write for a caller that holds MAIN’s write lock through main_lock, a TableWriteLock on the MAIN of ms (opened without locking), as a writer of several mutation sessions in turn holds it: MAIN’s metadata is written under it, the write recorded so that the caller’s release publishes it, and SOURCE’s lock is tried once, as while a caller holds MAIN’s through its handle.
virtual_model_fields
The fields with a virtual model pointer, definedmodel_field_<id>, in MAIN’s or SOURCE’s keywords, as the module states: those CASA’s iterator reads a virtual model for in place of MODEL_DATA. Only keywords are read.
