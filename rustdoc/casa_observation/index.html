Shared observation contracts for MeasurementSet v2 and MSv4: the VisibilityBatch that storage adapters fill and numerical consumers read, the AccessRequest consumers estimate and bind, and the Traversal of VisibilityCursors that delivers batches.

Trial status. This crate is the executable sketch of docs/measurement-set/contracts.md for the MSv2/MSv4 trial (docs/measurement-set/trial/README.md), at its third revision (docs/measurement-set/trial/revision-2-design.md, then the README’s “Revision 3”). Its interfaces are not frozen.

§The principle

MSv4 is the future: the interface takes MSv4’s native shape, and the MSv2 adapter assembles MSv2 data into it once, at opening. A consumer cannot tell the stores apart from a batch.

§The pieces

  • An Observation is the boundary algorithm code sees, whatever stores the data: its Catalogue names the antennas, fields, scans, observing sessions and partitions with identities scoped to that opening, and holds every per-partition constant once (channel frequencies and frame, correlation products, the baseline table, the time system, the data groups). Backend choice happens when the observation is opened.
  • A partition is a store unit described by its content: spectral window, correlation products, intents, observing session, feed pair. The MSv2 adapter partitions rows the way XRADIO’s converter does, so the same observation opens as the same partition set from either store.
  • An AccessRequest says what a traversal must deliver: the partition set, data group, roles (payload, time auxiliaries, scan), channel window, correlation products and flag policy, scientific grouping and the byte budget of one batch. Observation::estimate costs it from the catalogue and the store’s geometry alone (the batch shape: times per batch, bytes, read amplification, natural blocks, padding); Observation::bind_read binds it, refusing a role the store lacks, and returns one cursor per partition with the same Estimate.
  • A VisibilityCursor fills caller-owned BatchBuffers through one checked path (BatchBuffers::begin, BatchFill::finish) and lends them as a VisibilityBatch, or announces a ReadEvent::GroupEnd. Owned batches (FilledBatch) are filled into a bounded BufferPool and return their buffers when dropped; concurrent work on a group is joined by GroupCompletion’s WorkTokens. Within a cursor the traversal order is fixed: whole times of one channel window of one partition, in time order; across cursors it is the consumer’s.
  • A batch is whole times of the partition’s time × baseline grid: sample t × B + b, with the field and scan per time, its times, frequencies and UVW in native Measures views (casa_types::measures::EpochView and friends), the payload as ndarray views in the payload order [sample, channel, correlation], and one Validity rule over its flags, values and weights. A grid cell no acquisition filled is padding: flagged in every store (the MSv4 adapter folds XRADIO’s NaN weight into the flag), its values and time auxiliaries NaN.

§Example

A consumer binds a request against any observation, then loops over events; the borrow of the buffers ends before each refill.

use casa_observation::{AccessRequest, BatchBuffers, Observation, ObservationError, ReadEvent};

fn total_weight(
    observation: &dyn Observation,
    request: &AccessRequest,
) -> Result<f64, ObservationError> {
    let mut traversal = observation.bind_read(request)?;
    let mut buffers = BatchBuffers::default();
    let mut total = 0.0;
    while let Some(event) = traversal.next(&mut buffers)? {
        let ReadEvent::Batch(batch) = event else { continue };
        let (Some(weights), validity) = (batch.group.weights, batch.validity()) else {
            continue;
        };
        let [samples, channels, correlations] = batch.shape();
        for sample in 0..samples {
            for channel in 0..channels {
                for correlation in 0..correlations {
                    if !validity.excluded(sample, channel, correlation) {
                        total += f64::from(weights[[sample, channel, correlation]]);
                    }
                }
            }
        }
    }
    Ok(total)
}
