Reorganizing casa-rs into Deep, Publishable, UI-Decoupled, Agent-Legible Modules

After ~1 year of rapid development, casa-rs has grown to 1.04M lines of Rust across 35 flat crates in crates/. While imaging (ADR-0016) underwent a rigorous consolidation, the rest of the workspace accumulated severe boundary drift: domain crates depend upward on ~18.5k lines of multi-process contract/CLI plumbing left over from retired GUIs, 12 of 13 publish = true crates fail crates.io publication, 19 binaries sit inside library crates, two "god crates" (casa-ms 130kL, casa-calibration 118kL) mix unrelated subsystems, 50 files breach the 1,500-line ceiling, and tests compile into 345 separate link targets. This v3 proposal pairs compiler-enforced library boundaries (38 crates across 5 physical roots) with targeted ADR amendments (ADR-0017 in-process Python tasks, ADR-0006 protocol slimming, ADR-0011 uvcontsub relocation) to deliver maximum architectural simplicity, zero cycles, true UI decoupling, and out-of-the-box crates.io / docs.rs readiness.

Key Foundations: Codex Review Fixes (b84c228f82) + Recommended ADR Amendments
  • Preserved ADR-0016 imaging firewall & broke synthesis/SD/calibration cycles: Kept the 8-crate compiler-enforced DAG under libs/imaging/ (all publish = true, facade renamed casa-imaging), keeping casa-imaging-runtime below both casa-imaging-singledish and casa-imaging, and placing high-level casa-singledish above casa-calibration.
  • Fixed missing edges & kept casa-aipsio / casa-fft distinct: Added casa-ms → casa-measures; kept casa-aipsio as a small publish = true codec crate for C++ wire oracles (with a narrow table-header probe in casa-tables); kept pure casa-numerics separate from casa-fft so beam-only callers avoid FFTW.
  • Amended ADR-0017 & trimmed ADR-0006: Both casars.tools and casars.tasks run in-process in casars._core (via PyO3 over feature-gated surfaces/casa-tasks with GIL release + SIGINT → Cancel), sharing process-wide MeasuresRuntime and table caches; retired ~13.5kL of leftover GUI-era ProviderContractEnvelope, build.rs JSON-fingerprinting, and mandatory 23-binary child-process launcher scaffolding; kept frontends/casars-cli as a standalone shell/HPC CLI.
  • Relocated uvcontsub (ADR-0011) & hardened test / docs.rs mechanics: Moved visibility-domain fit_and_subtract_continuum from casa-imaging-operator to casa-mstransform; corrected test targets to 345 with allocator/CARGO_BIN_EXE exceptions; excluded opt-in suites/* from default --workspace; updated casa-fft/build.rs for Linux docs.rs.

Key Architectural Decisions & Tradeoffs (v3)

In-Process surfaces/ + Disposable frontends/

Amending ADR-0017 & slimming ADR-0006 collapses ~18.5kL of envelope/launcher boilerplate into ~7.5kL of typed casa-contracts + optional-feature-gated casa-tasks. casars.tasks in Python, casars-cli, and any experimental Web/Notebook/MCP UI all dispatch in-process with GIL release, Cancel tokens, and shared caches.

Preserving libs/imaging/ & Breaking Cycles

Keeping ADR-0016's Cargo boundaries preserves compile-time isolation and fast CARGO_INCREMENTAL=0 builds while publishing all 8 crates. Keeping casa-imaging-runtime below casa-imaging-singledish and casa-imaging, and placing casa-singledish above casa-calibration, eliminates both cycles cleanly.

Keeping casa-aipsio & casa-fft Separate

The C++ interop harness (aipsio_oracle.rs, table_sync.rs) tests raw AipsIO encoding directly, so keeping casa-aipsio small and publish = true beats hiding it. Keeping pure beams in casa-numerics separate from casa-fft ensures beam-only callers never link FFTW.

Clean Domain Seams (uvcontsub, Flagging, Transforms)

Relocating fit_and_subtract_continuum (uvcontsub) out of casa-imaging-operator into casa-mstransform matches CASA's domain model; casa-flagging & casa-mstransform stay free of casa-calibration via their existing model-input traits.

  • Test-driven API leaks: casa-imaging-application exports 8 pub mod *_law modules solely for integration tests; casa-ms::open_measures_runtime() swaps to casa-test-support under #[cfg(test)].

Should Tests Be Restructured First? — The Two-Beat Sequence

Beat 1 (Step 0 — Pin Existing Gates Before Moving Code)

  • Pin the existing acceptance commands as the immutable regression net: test-task-cli-hosts.py, cargo test -p casars-python, test-python-package.sh, test-install-suite.sh, test-casa-inventory.sh, test-release-cpp-interop.sh, imaging T0/T1/T1.5 & bounded-write laws.
  • Create opt-in suites/{casacore-interop,casa-parity,perf} (excluded from default --workspace) and move each suite together with its invoking script.
  • Route all test logs to target/test-logs/ so crate roots stay clean.

Beat 2 (Waves 1–4 — Per Crate As Modules Move)

  • Do not rewrite all 7,016 unit/API tests in place before moving crates — you would update imports twice.
  • Instead, in the same PR that lands each reorganized crate, collapse its fragmented tests/*.rs into tests/api.rs (keeping documented allocator/bin targets separate), retain memory counting laws as required checks, and delete its pub mod *_law / #[cfg(test)] leaks.

6. Deep Modules, Agent Understandability & Automated Guardrails

Ousterhout deep modules + agent-first layout + arch-check

Standard Deep-Module Crate Anatomy

Agents understand a crate by reading two files first: README.md and src/lib.rs. Every library crate follows one predictable, shallow-interface / deep-implementation shape: 

libs/casacore/casa-tables/
├── Cargo.toml           # complete crates.io + docs.rs metadata
├── README.md            # 15–25 lines: purpose, 1 snippet, non-goals
├── src/
│   ├── lib.rs           # ≤150 lines: #![warn(missing_docs)], crate doc,
│   │                    # curated public types + 2-6 topical pub mods
│   ├── error.rs         # single crate Error enum (thiserror)
│   ├── table/           # cohesive private implementation submodules (with #[cfg(test)])
│   ├── storage/         # internal storage managers (never re-exported raw)
│   └── taql/            # public topical sub-API (pub mod taql)
└── tests/
    └── api.rs           # default single black-box public API test binary

6 Agent-Ergonomics & Deep-Module Rules

  1. Curated facades over symbol dumps: src/lib.rs ≤ 150 lines; max 6 pub mods per crate; never expose internal helpers or test-law modules as pub mod.
  2. Single source of truth for modules: Ban dual foo.rs + foo/ pairs—pick either a single file foo.rs or foo/mod.rs so agents never guess where code lives.
  3. Strict 1,500-line ceiling (0 exceptions): Split the 50 grandfathered files (e.g., 14,497L tiled_stman.rs) into single-responsibility submodules and empty file-length-allowlist.json.
  4. Clean test isolation: No #[cfg(test)] production behavior swaps (delete the open_measures_runtime test hook); inject dependencies explicitly via constructors/traits.
  5. Zero repository clutter: Route test logs to target/test-logs/ via harness setup; delete orphan dirs and stale site/ GUI pages.
  6. Predictable naming: casa-<domain> for publishable libs, surfaces/casa-* for UI-agnostic plumbing, frontends/casars-* for UIs, and suites/* for opt-in verification.

Most of the existing ADRs encode strong systems engineering (bounded streaming, on-disk interoperability, ownership-based identity, single-investigator focus). Two ADRs—ADR-0017 and the leftover multi-process machinery around ADR-0006—are actively forcing binary sprawl and ~13.5kL of avoidable plumbing.
