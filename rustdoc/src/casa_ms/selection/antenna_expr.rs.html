2//! CASA's antenna (baseline) selection expressions, ported from casacore.
3//!
4//! [`resolve_antenna_selector`] parses the `antenna=` text of an
5//! `MSSelection` and resolves it against the ANTENNA table into a
6//! [`BaselineSelection`]: for every ordered (`ANTENNA1`, `ANTENNA2`) pair of
7//! a MAIN row, whether CASA would select that row. It follows casacore at
8//! commit `aaf72eb7` (the casacore of CASA 6.7.6.14): the scanner
9//! `ms/MSSel/MSAntennaGram.ll`, the grammar `MSAntennaGram.yy`, the
10//! selection logic `MSAntennaParse.cc` and the name lookups
11//! `MSAntennaIndex.cc`. Where these have quirks, CASA's behaviour is kept
12//! and the quirk is noted below.
13//!
14//! # Expressions
15//!
16//! An expression is one or more *terms* separated by `;`. A term is a
17//! baseline form applied to antenna lists, a baseline-regex list or a
18//! baseline-length list, optionally negated by a leading `!`.
19//!
20//! | Form | Selects (cross = `ANTENNA1 != ANTENNA2`) | C++ |
21//! |---|---|---|
22//! | `L` | cross baselines with an antenna of `L` on either side | `MSAntennaGram.yy:193-201`, `MSAntennaParse.cc:123-130,84-89` |
23//! | `L1&L2` | cross baselines with one side in `L1` and the other in `L2`, in either order | `.yy:168-178`, `.cc:157-176` |
24//! | `L&` | cross baselines between antennas of `L` | `.yy:179-192` |
25//! | `L1&&L2` | as `L1&L2`, also the autocorrelations of antennas in both lists | `.yy:202-212` |
26//! | `L&&` | as `L&` plus the autocorrelations of `L` | `.yy:213-221` |
27//! | `L&&&` | only the autocorrelations of `L` | `.yy:222-230`, `.cc:105-121` |
28//! | `/A&B/` (a regex holding `&`) | ordered pairs whose `NAME1&NAME2` the regex matches in full; autocorrelations too | `.ll:83-86`, `.cc:250-277` |
29//! | `<x`, `<=x`, `>x`, `>=x`, `a~b` with a length unit | baselines whose ITRF length lies in the interval, autocorrelations (length 0) too | `.yy:453-506`, `.cc:230-248,311-334` |
30//! | `!T` | the rows `T` does not select | `.yy:165`, `.cc:91` |
31//! | `T1;T2` | left to right: a plain term ORs with what precedes it, a `!` term ANDs | `.cc:92-95` |
32//!
33//! An antenna list `L` is a comma-separated list of:
34//!
35//! | Item | Antennas | C++ |
36//! |---|---|---|
37//! | name, e.g. `ea01` | rows whose NAME equals it; if none, rows whose STATION equals it | `.yy:293-306`, `MSAntennaIndex.cc:126-158` |
38//! | integer, e.g. `5` | the first row whose NAME (else STATION) is that text, else antenna ID 5 | `.yy:336-357` |
39//! | range `3~7` | each integer as above, its name written in plain decimal | `.yy:358-380` |
40//! | pattern, quoted (`"ea0*"`, `'ea{01,02}'`) or bare (`ea0*`, `ea0[1-3]`) | rows whose NAME, else STATION, matches in full; a leading `^` negates | `.ll:46-63,111-116`, `MSAntennaIndex.cc:82-122`, `Regex::fromPattern` |
41//! | regex `/ea0[1-3]/`, negated `^/.../` | as a pattern, the text an ECMAScript regex | `.ll:49,77-87` |
42//! | `\text` | the name `text`, which may then hold any non-blank characters | `.ll:59,104-109` |
43//! | `A@S`, `(A1,A2)@S`, `A@(S1,S2)`, `@S` | antennas of `A` standing at a station of `S` (exact STATION, pattern or regex) | `.yy:249-289,416-438` |
44//!
45//! Every name, pattern, station or ID that matches nothing is an error,
46//! raised once the whole expression has been read (`reportError`,
47//! `MSSelection.cc:858-864`), as are scanner and syntax errors, units that
48//! are not lengths and regexes that do not compile. The empty string is no
49//! constraint (`MSSelection.cc:590`); text of only blanks is a syntax error.
50//!
51//! # CASA quirks this port keeps
52//!
53//! - A purely numeric item is a NAME first: with an antenna named `"3"`,
54//!   `3` selects that antenna, not ID 3; only its first such row is kept
55//!   (`.yy:352-355`). A range looks up `std::ostringstream` decimal names,
56//!   so `01~02` looks up `"1"` and `"2"` while a lone `01` looks up `"01"`.
57//! - Integers are read with `atoi`: `4294967296` is antenna 0 (glibc keeps
58//!   the low 32 bits). A range `a~b` whose length `b - a + 1` is below zero
59//!   or overflows `Int` (`0~2147483647`) is an error, as the C++ `Vector`
60//!   allocation fails; a range reaching past the last antenna selects the
61//!   antennas that exist without complaint.
62//! - `!T` also selects every autocorrelation `T` excludes: `!ea01` selects
63//!   ea01's own autocorrelation, since `T` masks autocorrelations before
64//!   the negation (`.cc:84-91`).
65//! - `;` is not commutative: `ea01;!ea02` is (ea01 baselines) AND NOT
66//!   (ea02 baselines), but `!ea02;ea01` is (NOT ea02 baselines) OR (ea01
67//!   baselines).
68//! - A leading `^` inside a regex or pattern is negation, not an anchor:
69//!   `/^ea0[12]/` selects every antenna but ea01 and ea02.
70//! - Patterns and regexes fall back to STATION per antenna; exact names fall
71//!   back to STATION only when no NAME matches at all.
72//! - A baseline regex is matched against the ordered string
73//!   `NAME(ANTENNA1)&NAME(ANTENNA2)`, so `/ea01&ea02/` selects the rows with
74//!   ANTENNA1 = ea01 and ANTENNA2 = ea02 but not the reverse; one that
75//!   matches nothing selects nothing silently (`.cc:299-308`).
76//! - Length forms: `<x` and `>x` move the bound by 1e-9 m; a range of plain
77//!   integers with a unit (`100~200m`) is an antenna-ID range followed by a
78//!   stray unit, hence a syntax error: write `100m~200m` or `100.~200.m`.
79//! - Concatenated quotes keep their inner quotes (`"ea"'01'` is the
80//!   pattern `ea"'01`, `.ll:69-75`).
81//!
82//! # Not ported
83//!
84//! - ECMAScript backreferences, lookahead and `\u` escapes in regexes are
85//!   refused: the `regex` crate has none of them.
86//! - ANTENNA `POSITION` is read as ITRF, as everywhere in casa-ms; CASA
87//!   converts other reference frames with `MPosition::Convert`.
88//! - The side lists `MSSelection::getAntenna1List`, `getAntenna2List` and
89//!   `getBaselineList` are not produced; only the row predicate is.
90//! - Messages follow CASA's wording but not its character positions
91//!   exactly.

108/// One ANTENNA table row as antenna selection reads it. In a slice of these,
109/// row `i` is antenna ID `i`.
110///
111/// Cf. the NAME, STATION and POSITION columns `MSAntennaIndex` and
112/// `MSAntennaParse::getBaselineLengths` read. `FLAG_ROW` plays no part:
113/// casacore's checks of it are commented out (`MSAntennaIndex.cc:117`).
114#[derive(Clone, Copy, Debug, PartialEq)]
115pub struct AntennaRow<'a> {
116    /// The NAME column, compared exactly (no trimming, case-sensitive).
117    pub name: &'a str,
118    /// The STATION column, compared exactly.
119    pub station: &'a str,
120    /// The POSITION column: ITRF geocentric `[x, y, z]` in metres. Only
121    /// baseline-length terms (`<100m`, `1km~2km`) use it.
122    pub position_m: [f64; 3],
123}
124
125/// A resolved antenna selection: which ordered (`ANTENNA1`, `ANTENNA2`)
126/// pairs of MAIN rows CASA's `MSSelection` would keep.
127///
128/// It holds a dense `(n + 2) × (n + 2)` table of booleans for `n` antennas.
129/// The two extra entries on each side stand for antenna IDs that are not
130/// ANTENNA rows: CASA's TaQL compares such an ID with no listed antenna, so
131/// the answer for one depends only on whether it equals the other side.
132/// An empty expression holds no table and selects everything.
133#[derive(Clone, Debug, PartialEq, Eq)]
134pub struct BaselineSelection {
135    antenna_count: usize,
136    /// Row-major over `0..antenna_count + 2`; `None` when unconstrained.
137    pairs: Option<Box<[bool]>>,
138}
139
140impl BaselineSelection {
141    fn unconstrained(antenna_count: usize) -> Self {
142        Self {
143            antenna_count,
144            pairs: None,
145        }
146    }
147
148    /// The number of ANTENNA rows the expression was resolved against.
149    pub fn antenna_count(&self) -> usize {
150        self.antenna_count
151    }
152
153    /// Whether the expression was empty, so every row is selected.
154    pub fn is_unconstrained(&self) -> bool {
155        self.pairs.is_none()
156    }
157
158    /// Whether a MAIN row with these `ANTENNA1` and `ANTENNA2` values is
159    /// selected. The order matters only for baseline-regex terms.
160    ///
161    /// IDs at or past [`antenna_count`](Self::antenna_count) are answered as
162    /// CASA's row predicate answers them: they match no name, station,
163    /// pattern or ID, so for example `!ea01` selects them and `ea01` does
164    /// not.
165    pub fn holds(&self, antenna1: usize, antenna2: usize) -> bool {
166        let Some(pairs) = &self.pairs else {
167            return true;
168        };
169        let count = self.antenna_count;
170        let row = antenna1.min(count);
171        let column = if antenna2 < count {
172            antenna2
173        } else if antenna2 == antenna1 {
174            count
175        } else {
176            count + 1
177        };
178        pairs[row * (count + 2) + column]
179    }
180
181    /// The heap bytes this selection owns: its pair table, one byte per
182    /// entry, `(n + 2)²` for `n` antennas, or nothing when unconstrained.
183    pub fn allocated_bytes(&self) -> usize {
184        self.pairs.as_ref().map_or(0, |pairs| size_of_val(&**pairs))
185    }
186}

188/// Resolve CASA antenna selection `text` against `antennas`, the ANTENNA
189/// table's rows in row order.
190///
191/// The empty string is no constraint, as `MSSelection` skips an empty
192/// antenna expression. See the [module documentation](self) for the
193/// expression forms and how each selects baselines.
194///
195/// # Errors
196///
197/// [`MsError::InvalidInput`], worded as CASA's
198/// `MSSelectionAntennaParseError`, when the text does not scan or parse,
199/// when any name, pattern, regex, station or ID in it matches no antenna,
200/// when a length unit is unknown or not a distance, or when a regex does
201/// not compile or uses an ECMAScript feature the port lacks.
202pub fn resolve_antenna_selector(
203    antennas: &[AntennaRow<'_>],
204    text: &str,
205) -> MsResult<BaselineSelection> {
206    if text.is_empty() {
207        return Ok(BaselineSelection::unconstrained(antennas.len()));
208    }
209    let index = AntennaIndex::new(antennas);
210    let parsed = grammar::parse(&index, text)
211        .map_err(|(abort, reports)| failure(text, &reports, Some(abort)))?;
212    if !parsed.reports.is_empty() {
213        return Err(failure(text, &parsed.reports, None));
214    }
215    Ok(BaselineSelection {
216        antenna_count: antennas.len(),
217        pairs: Some(evaluate(&parsed.clauses, antennas.len())),
218    })
219}

221impl MeasurementSet {
222    /// Resolve CASA antenna selection `text` against this MeasurementSet's
223    /// ANTENNA table (NAME, STATION and POSITION), as
224    /// [`resolve_antenna_selector`] does over rows a caller supplies.
225    ///
226    /// Reads only the ANTENNA subtable; MAIN is not scanned.
227    ///
228    /// # Errors
229    ///
230    /// An unreadable ANTENNA table, or any refusal of
231    /// [`resolve_antenna_selector`].
232    pub fn resolve_antenna_selector(&self, text: &str) -> MsResult<BaselineSelection> {
233        let antenna = self.antenna()?;
234        let count = antenna.row_count();
235        if text.is_empty() {
236            return Ok(BaselineSelection::unconstrained(count));
237        }
238        let mut columns = Vec::with_capacity(count);
239        for row in 0..count {
240            columns.push((
241                antenna.name(row)?,
242                antenna.station(row)?,
243                antenna.position(row)?,
244            ));
245        }
246        let rows: Vec<AntennaRow<'_>> = columns
247            .iter()
248            .map(|(name, station, position_m)| AntennaRow {
249                name,
250                station,
251                position_m: *position_m,
252            })
253            .collect();
254        resolve_antenna_selector(&rows, text)
255    }
256}

258/// One term and whether `!` negates it.
259struct Clause {
260    term: Term,
261    negate: bool,
262}
263
264/// The row condition of one term, over existing antenna IDs.
265enum Term {
266    /// `selectAntennaIds(ids, CrossOnly)`: either side in the list.
267    Cross(Vec<usize>),
268    /// `selectAntennaIds(first, second, type)`: one side in each list.
269    Pair {
270        first: Vec<usize>,
271        second: Vec<usize>,
272        autocorrelations: bool,
273    },
274    /// `selectAntennaIds(ids, AutoCorrOnly)`.
275    AutoOnly(Vec<usize>),
276    /// `makeBLNode`: an `n × n` row-major table of selected ordered pairs.
277    Ordered(Vec<bool>),
278}
279
280/// Evaluate the terms over every (`ANTENNA1`, `ANTENNA2`) slot, as
281/// `MSAntennaParse::setTEN` (`MSAntennaParse.cc:80-98`) combines them.
282fn evaluate(clauses: &[Clause], count: usize) -> Box<[bool]> {
283    let side = count + 2;
284    let mut selected = vec![false; side * side].into_boxed_slice();
285    for (position, clause) in clauses.iter().enumerate() {
286        let condition = condition(&clause.term, count);
287        for antenna1 in 0..side {
288            for antenna2 in 0..side {
289                let value = condition(antenna1, antenna2) != clause.negate;
290                let cell = &mut selected[antenna1 * side + antenna2];
291                *cell = if position == 0 {
292                    value
293                } else if clause.negate {
294                    *cell && value
295                } else {
296                    *cell || value
297                };
298            }
299        }
300    }
301    selected
302}

304/// The row condition of `term` over slots `0..count + 2`; slots from
305/// `count` on are IDs no list contains.
306fn condition(term: &Term, count: usize) -> Box<dyn Fn(usize, usize) -> bool + '_> {
307    let side = count + 2;
308    let mask = move |ids: &[usize]| {
309        let mut members = vec![false; side];
310        for &id in ids {
311            members[id] = true;
312        }
313        members
314    };
315    match term {
316        Term::Cross(ids) => {
317            let members = mask(ids);
318            Box::new(move |a1, a2| a1 != a2 && (members[a1] || members[a2]))
319        }
320        Term::Pair {
321            first,
322            second,
323            autocorrelations,
324        } => {
325            let (first, second) = (mask(first), mask(second));
326            let autocorrelations = *autocorrelations;
327            Box::new(move |a1, a2| {
328                (autocorrelations || a1 != a2)
329                    && ((first[a1] && second[a2]) || (second[a1] && first[a2]))
330            })
331        }
332        Term::AutoOnly(ids) => {
333            let members = mask(ids);
334            Box::new(move |a1, a2| a1 == a2 && members[a1])
335        }
336        Term::Ordered(table) => {
337            Box::new(move |a1, a2| a1 < count && a2 < count && table[a1 * count + a2])
338        }
339    }
340}

342/// The `MsError` for a refused expression. "No match" reports win over the
343/// error that stopped the parse, as `MSSelection::toTableExprNode` runs
344/// the error handler before rethrowing (`MSSelection.cc:759-765`); their
345/// text is `MSSelectionErrorHandler::constructMessage`
346/// (`MSSelectionErrorHandler.cc:63-77`).
347fn failure(text: &str, reports: &[Report], abort: Option<Abort>) -> MsError {
348    let message = match (reports.first(), abort) {
349        (Some(first), _) => {
350            let mut message = first.message.clone();
351            for report in reports {
352                message.push_str(&report.token);
353                message.push(' ');
354            }
355            message.trim_end().to_string()
356        }
357        (None, Some(Abort(message))) => message,
358        (None, None) => String::from("Antenna Expression: no selection"),
359    };
360    MsError::InvalidInput(format!("antenna selection {text:?}: {message}"))
