Antenna configuration files: CASA’s simutil.readantenna.

simobserve and simalma read the array from a text file such as CASA’s alma.cycle10.3.cfg:

# observatory=ALMA
# coordsys=LOC (local tangent plane)
# x             y               z             diam  station  ant
-5.850273514   -125.9985379    -1.590364043   12.   A058     DA41
-19.90369337    52.82680653    -1.892119601   12.   A023     DA42

read_antenna_config reads one and returns what CASA’s readantenna returns: Earth-centred (ITRF) antenna positions, dish diameters, pad and antenna names, the telescope name and the observatory position.

§The format

  • Header lines start with #. When the text after the # holds exactly one =, the two sides, stripped of every # and of surrounding white space, are a key=value parameter; the key is all the text before the =. Other header lines are comments. Headers may appear anywhere, and a later duplicate wins.
  • Antenna lines lose everything from their first #. Their white-space-separated columns are x, y, z, diameter (metres, parsed as Python’s float), the pad (station) name and the antenna name. With five columns the pad is also the antenna name; with four, both are A%02d for the antenna’s index.
  • coordsys (required) says what x, y, z are. Its value is upper-cased; XYZ and UTM must match exactly and LOC matches its first three characters (CASA’s own files say coordsys=LOC (local tangent plane)).
    • XYZ: ITRF x, y, z, used as they are.
    • UTM: easting, northing and elevation, with the required headers zone, datum (a code of geodesy::DATUMS, case-sensitive) and hemisphere (south when its first letter is S or s), converted with geodesy::utm_to_xyz.
    • LOC: east, north and up offsets from the observatory, converted with geodesy::local_to_itrf at the observatory’s geodetic WGS 84 latitude, longitude and height.
  • observatory names the telescope (SIMULATED without one).
  • COFA=lon,lat (degrees) sets the observatory position, at height zero; it overrides a known observatory, with a warning.

§The observatory position

In CASA’s order:

  1. COFA, when given.
  2. A known observatory: the measures provider’s observatory table (CASA’s me.observatory), converted to WGS 84. The name matches as casacore’s MeasTable::Observatory matches it: a case-insensitive exact match, else the one table name that is a prefix of the telescope name (CASA’s aca.tp.cfg says observatory=ALMASD, which is ALMA). Two such names (GB and GBT for GBTX) match none.
  3. Otherwise a LOC file is an error, and for absolute coordinates the observatory is the mean antenna position, converted to WGS 84 with geodesy::xyz_to_geodetic.

The position is returned in WGS 84, as CASA returns it.

§Where this differs from CASA

CASA’s readantenna has bugs on some paths. These follow its evident intent instead. Each was confirmed by running CASA 6.7.6 unless it says otherwise.

  • Blank and short lines. Lines that are neither headers nor antennas (blank lines, lines with fewer than four columns) are skipped. CASA means to skip them (pass # ignore empty rows) but appends a default A%02d pad and antenna name for each, numbered by line. Its name lists then outgrow the positions and pair with the wrong antennas: for CASA’s WSRT.cfg, whose header has two blank lines, it returns 16 names for 14 antennas, starting A00, A01, RT0.
  • The mean position. For an unknown observatory without COFA, CASA averages the loop variable x left over from the coordinate conversion. For XYZ files that variable does not exist and CASA raises UnboundLocalError; for UTM files it is the last antenna’s x, y, z. CASA also unpacks xyz2long’s longitude, latitude, height as latitude, longitude, height, so its position has the two angles swapped. Here the observatory is xyz2long of the mean of the ITRF antenna positions, as CASA’s comment says.
  • Errors.
    • A coordsys that is none of XYZ, UTM, LOC… is an error. CASA returns no positions (and, through the blank-line bug, one name per antenna line).
    • A non-integer zone, an empty hemisphere and a malformed COFA are errors with messages in CASA’s style, where CASA lets Python’s ValueError or IndexError escape.
    • A number that does not parse is CASA’s Could not read file error, with the line and the text added.
    • zone and datum are checked even when there are no antennas, where CASA never converts them (from CASA’s source).
  • Unresolvable names. CASA counts a telescope as known when any table name is a substring of it, then looks it up with me.observatory, which can fail (xALMAx). CASA then raises KeyError for a LOC file and takes the mean-position path otherwise; here such a name is simply unknown.
  • Prefix ambiguity. casacore also counts a longer table name that starts with the telescope name as a candidate (MWA3 matches both MWA and MWA32T, so neither; from casacore’s MUString::minimaxNC). The measures provider only answers exact lookups and cannot list its table, so that case resolves to the shorter name here.
  • COFA height. The observatory is at height 0. casacore stores a zero-height WGS 84 position as a 1e-6 m vector, so CASA’s position, and the height its LOC conversion uses, is 1e-6 m.
  • Conversion to WGS 84 of an observatory tabulated in ITRF uses MPosition::convert_to (SOFA’s gc2gd) rather than casacore’s iteration. For real sites they agree to about 1e-14 rad and 1e-9 m. CASA’s table also has placeholder entries at or near the geocentre (VLBA and EVN at ITRF (1e-6, 0, 0) m; LOFAR, OVRO_MMA and SUNRISE within a kilometre of it), whose geodetic positions are meaningless either way: for CASA’s vlba.cfg CASA’s observatory is (0, 0, 742.93 m) and this one (0, 0, −6378137 m). XYZ antenna positions do not depend on it.
  • Numbers with non-ASCII decimal digits, which Python’s float accepts, are rejected (from Python’s documentation).
