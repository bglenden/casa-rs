    A taxonomy of interferometric imaging modes for casa-rs performance work¶

    Truth class: non-normative research Date: 2026-10-16 Work issue: #449 (the 10x programme); the slower modes it identifies are tracked in their own issues.

    Written 2026-10-16 from the Radio Astronomy Oracle corpus, the casa-rs imaging foundation (plan of 2026-10-07 as landed by IF-11), the imager parameter catalog, and CASA's tclean definition. No code was changed and no runs were made for it. Speedups quoted in sections 4 and 5 are the measurements on record on that date (the #648 evidence table and the run receipts); later measurements are recorded on #449, not here.

    Purpose: replace labels like "standard MFS Clark" with a small set of independent axes, so that (a) measured speedups against CASA sit on a grid, (b) each mode's cost drivers are explicit, and (c) a short benchmark set can be chosen for the 10x programme whose target is VLASS-style AW-projection MT-MFS at 12,150 pixels square.

    Citation conventions. Corpus items are cited as File.pdf, slide N or File.pdf, p. N (PDF page, as the corpus registry numbers them). casa-rs is cited by file and section or line (plan §5.3 is docs/imaging-architecture/imaging-foundation-plan-20261007.md; ARCHITECTURE.md L567 is a line in that file; catalog:parameter.x is an id in crates/casa-provider-contracts/resources/parameter-catalog.json). CASA is cited as tclean.xml L123 (casatasks/xml/tclean.xml) or a C++ file and line. Where a number is my own derivation from a cited relation, it says so.

    0. Vocabulary¶

    • Sample: one selected row x channel x correlation before flagging (N_s). casa-rs grids one Placement per sample after flagging and routing (plan §5.3).
    • Pass (major cycle): one traversal of the samples that grids V or V − A·m into every image domain, followed by the FFT and normalisation (ARCHITECTURE.md L567-586; Synthesis-Imaging-II-1998.pdf, p. 179).
    • Minor cycle: image-plane component search and PSF subtraction between passes (Marvil_Imaging2026.pdf, slide 30).
    • Kernel support N_sup: the width in uv cells of the convolution function one sample touches; the cost per sample is N_sup² (Jagannathan-Widefield.pdf, slide 33, 35).
    • Convolution function (CF) cell: one stored kernel for one (w-plane, frequency, parallactic angle, antenna pair, Mueller row) key (plan §5.3 CfKey, §5.6).
    • Plane: one output spectral channel's grid; term: one Taylor coefficient grid (plan §5.1).
    • Image domain: a main image, an outlier field or a facet, each with its own grid (ARCHITECTURE.md L573-575, L646-655).
    • PB: primary beam; flat noise divides the image by one PB, flat sky by PB² (Jagannathan-Widefield.pdf, slide 29; tclean.xml L1275).
    • N_pix image pixels per plane, N_pl planes, N_t Taylor terms, N_maj passes after the initial one, N_iter minor-cycle components.

    1. Axes¶

    Nine axes describe a run. Sizes (samples, pixels, planes, terms, iterations) are not axes; they are the numbers each axis value multiplies (section 2).

    When each correction is needed: the w-term matters for baselines beyond B_thresh = D²/(πλ) (about 950 m for the VLA at L band; nearly every MeerKAT baseline) (Jagannathan-Widefield.pdf, slide 13; Perley-Geometry-SIW2026.pdf, slide 12 gives the equivalent Clark condition λB/D² < 1). The A-term matters when sources sit where the beam varies with frequency (beam scales as λ, spectral index about −1.4 at the half-power point), with time (parallactic angle rotates the feed-leg shadows) or polarisation (squint) (Jagannathan-Widefield.pdf, slide 23-26; URV_Wideband_Imaging_SIW2026.pdf, slide 22; Synthesis-Imaging-II-1998.pdf, p. 132).

    1.10 Size parameters¶

    These are not modes but they decide which cost term wins (section 2.3).

    • N_s: rows x channels x correlations selected. VLA: "351 baselines, 1000+ channels every 2-5 seconds = 200M samples/hour" (Marvil_Imaging2026.pdf, slide 5). Channel averaging is bounded by bandwidth smearing, δν < ν0·D/b_max (1 MHz for VLA A, 30 MHz for D) (URV_Wideband_Imaging_SIW2026.pdf, slide 41), so N_s is set by the science, not by the imager.
    • N_pix: image pixels per plane. Cell oversamples the synthesised beam by 4-5 (Marvil_Imaging2026.pdf, slide 14) or 5-7 (Butterfield-ErrorRecognition-SIW2026.pptx, slide 41); the field is the full primary beam, or the mosaic. The uv cell is 1/(N·Δl) (Marvil_Imaging2026.pdf, slide 15), so for a fixed cell a larger image means finer uv cells and wider kernels in cells (section 2.1).
    • N_pl, N_t, N_dom (image domains), N_pol.
    • N_maj and N_iter: outputs of the cycle controller, inputs to cost.

    2. Cost model¶

    2.1 Cost terms¶

    Symbols: N_s samples after flagging, N_sup kernel width in cells, N_mu Mueller planes routed per sample (1 for Stokes I), N_t terms, N_pix, N_pl, N_dom, N_pol, N_maj residual passes, N_iter components, N_sc scales, N_cf distinct CF cells.

    Term Scaling Notes and sources
    G gridding and degridding N_s · N_sup² · N_mu · N_dom · (N_t grid + N_t degrid) · (1 + N_maj); the first pass also grids 2N_t−1 PSF terms and, for M/AW, one weight grid Gridding cost ∝ N_vis × N_sup²: prolate spheroidal 3x3 to 7x7, A-term about 9x9, W-term up to 200x200 (4000x the spheroidal); "approximately 80% of total imaging cost" (Jagannathan-Widefield.pdf, slide 35-36; Jagannathan-Widefield2024.pdf, slide 26); O(Mm²) (Synthesis-Imaging-II-1998.pdf, p. 167); casa-rs kernel contract (plan §5.3)

    2.3 Cost regimes¶

    Six regimes cover the combinations that matter. Each is recognised from numbers a run summary already has: samples, pixels, planes, terms, kernel width, passes, iterations.

    Regime Dominant term Recognise it when Levers
    R1 sample-dominated, narrow kernel G with N_sup = 7 N_s · 49 · (1+N_maj) ≫ 50 · N_pix log N_pix · N_pl · (1+N_maj), i.e. samples per output pixel per pass ≳ 20 and K = S Per-sample fixed costs, memory bandwidth of grid updates, worker partition (planes vs regions), Metal
    R2 kernel/CF-dominated G with N_sup ≥ 15, plus C K ∈ {W, M, AW} and a large field: N_sup² of 200-40,000; or N_cf large relative to samples per cell (cache misses) Kernel storage layout, tap loop, CF residency, dropping Mueller planes not routed, pass order by CF group
    R3 pixel-dominated F and P samples per pixel per pass ≲ 10 and N_pix ≥ 1.7e7; cost roughly constant when N_s changes (the pilot rows: x4 samples gave 44.8 → 46.5 s) FFT plan, normalisation passes, product writers, f32 vs f64 grids
    R4 deconvolution-dominated D N_iter ≥ 1e4, or N_iter · N_pix · N_sc comparable to G; many Clark cycles each refreshing by FFT; deep thresholds Active lists, incremental peak search, patch size, cycle control, threads per plane
    R5 memory/I/O-bound I N_pix · N_pl · N_t · N_pol · bytes above about a quarter of RAM (waves, paging, swap); or wM/wC; or N_s · 13 B · traversals beyond disk bandwidth x wall Residency plan, grid precision, column write path, read-ahead
    R6 fixed-cost/startup-dominated process start, table open, CF generation, plan time wall under about 30 s; ratios vary run to run by 2x Not usable for speedup claims; diagnostic only

    2.4 Scaling the regimes to the 12,150-pixel VLASS target¶

    Same data (167.7 M samples), same cell (0.6"), 2.97x the image side:

    • F, P, I: N_pix x8.8, N_pix log N_pix x9.9. One complex f64 grid plane is 2.36 GB; an MT-MFS first pass holds 2 data + 3 PSF + 1 weight grids, so 14 GB in f64 or 7 GB in f32 for one worker, before images, FFT scratch and CF cells. On a 32 GB laptop this is R5 territory; gridprecision and the number of region workers decide whether the first pass fits (ARCHITECTURE.md L667-670; plan §5.4). CASA's own 12,150² runs peaked at 12.8-13.8 GB RSS with 361-411 GB of swap-in (vlass-imaging-recovery-contract.md L263-269, L318-323).
    • G: the A-term support grows x2.97 (so N_sup² x8.8); W-dominated kernels grow x8.8 in width (N_sup² x78). The per-sample kernel cost therefore rises between 9x and 78x depending on how many samples are W-dominated at 12,150². CASA's own ratio between its 4096² and 12,150² 63-field clean references is 82,352 / 9,074 = 9.1, which matches the pixel-count and A-term scalings and not the W-term extreme; whether that is because few samples are W-dominated or because CASA is pixel-bound there is open (section 6). Reading the frozen CF cache headers (support per cell, which AwCatalog::open_casa reads at open; plan §5.6) would settle the kernel widths without a run.
    • D: niter 20,000 (casa-b) on 1.48e8 pixels with 3 scales and 2 terms: a non-incremental peak search is 2e4 · 1.5e8 · 3 ≈ 9e12 compares, more than the gridding. CASA's casa-b selected only 444 components across eight minor cycles before its n-sigma stop (vlass-imaging-recovery-contract.md L231-233), so in CASA's run D was small; a casa-rs run that cleans deeper would move into R4.
    • C: N_cf is unchanged (same planes, frequency cells, PA cells) but each cell is N_sup²·oversampling² larger: 9-78x the bytes, so the resident set under cf_resident_mb shrinks and misses rise.

    So the 12,150² rows are R2 with R5 pressure and a possible R4 tail; the 4096² rows are R2 alone. A benchmark set for the 10x goal must therefore measure the kernel width growth (R2), the first-pass memory plan (R5) and the minor cycle at 1.5e8 pixels (R4) separately.

    Reading the set against the target:

    • B2 → B3 gives first-pass versus residual-pass AW cost at 4096²; B4 gives the first pass at 12,150² with few samples; B6 at both sizes gives the W share. Together they predict casa-b's per-pass cost as pass(4096²) × support growth, where the growth is measured, not assumed.
    • B1 and B5 bracket the minor cycle at the two sizes with the same niter.
    • B7 and B8 give the standard-kernel floors (pixel-bound and sample-bound) that any AW improvement cannot pass.
    • B9 and B10 keep the cube and mosaic regimes measured without long runs.

    Gaps: no frozen CASA time for the single-field or 63-field dirty 12,150² rows (two of the four acceptance rows), or for B6, B8 or B9 (#827); the 63-field 12,150² rows cannot be made minutes-long on a laptop by any selection that keeps the geometry (casa-b took CASA 22.9 h); no dataset in casatestdata gives a W-projection or AW row above R6 (the refim_* MSs are 1-183 MB), so the VLASS fragment is the only wide-field source at scale; vla_wideband_2ptg_w_squint.ms and refim_mawproject.ms are 1 KB stubs on the NAS copy and need the real files before they can seed anything.

    6. Open questions¶

    1. Kernel widths at 12,150². The sources give ranges (7-50 cells for A and mosaic kernels, "significantly larger" with W, up to 200x200; tclean.xml L791-817; Jagannathan-Widefield.pdf, slide 36) and one scaling statement ("support scales with w_max", slide 16). The θ² growth of the W kernel is my derivation from the slide-13 phase; it predicts a 9x to 78x kernel-cost increase from 4096² to 12,150², while CASA's own clean references scale by 9.1x. Either most VLASS samples are not W-dominated at 12,150², or CASA is pixel-bound there. The frozen CF cache headers answer the first half without a run.
    2. CASA's single-field time is nearly size-independent: 3,631.8 s at 4096² with 4 SPWs against 3,798 s at 12,150² with 16 SPWs (4x samples, 8.8x pixels). Something fixed dominates CASA's single-field AW runs (CF cache fill, restoration of 19 products, or its minor cycle); the recovery contract does not record the cache state of the 4096² reference. CASA's stage timers for both runs would show it. Until then a single-field speedup says little about the 63-field one, which the contract already forbids inferring (vlass-imaging-recovery-contract.md L519-522).
    3. Where the MT-MFS minor cycle sits at 1.5e8 pixels. The corpus gives the algorithm (Marvil_Wideband2024.pdf, slide 20-21) but no cost model; casa-rs's Taylor solver (plan §5.5) does not state whether its peak search is incremental. The small AW rows (45x dirty, 19x clean) suggest casa-rs's minor cycle share is larger than CASA's. B1 versus B5 measures it.
    4. W-projection at or below CASA at 512² (1.1x). Whether WPlanes generation is a fixed cost or grows with samples is unmeasured above R6; B6 answers it (#827). The mosaic half of this question is closed: #787 brought the 512² mosaic rows to 1.43x and 1.79x, and B10 and B11 to 8.37x and 5.17x on their best plans.
    5. MODEL_DATA writes at 0.63-0.67x. Column write or prediction pass: the optional row separates them.
    6. Equal-work comparisons. L4 ran 23 major cycles against CASA's 15, and L1 17 against an unrecorded CASA count; the speedups mix cycle control with throughput. TESTING.md L509-512 asks for --nmajor caps; the per-pass figures in 4.1 are my division, not a measurement.
    7. Standard kernel width. The corpus says 3x3 (Jagannathan-Widefield.pdf, slide 34-35), the book says m = 6 cells (Synthesis-Imaging-II-1998.pdf, p. 167), CASA says 7x7 (tclean.xml L747), casa-rs half-support 3 (plan §5.1). These are the same kernel described by half-width, width and tap count; cost models should use 49 taps.
    8. Which recipe is "the" wideband mosaic. CASA's own guidance is specmode='mvc' for wideband mosaics (URV_Wideband_Imaging_SIW2026.pdf, slide 23, 25); the VLASS recipe under test is mfs + AW + conjbeams, and mvc is not in the casa-rs catalog (ARCHITECTURE.md L657-658). The 10x target is defined on the VLASS recipe; a future mvc would be a different signature (mvc/AW…) and a different regime (cube passes).
    9. AW on more than one CPU worker. L5 ran one worker; no large AW row records W4, so the Partition::Regions scaling of wide kernels (halo size grows with N_sup) is unknown. B3 at W1 and W4 would show it.
    10. Cube weighting. perchanweightdensity and briggsbwtaper are recommended for cubes (Plunket-Mosaicking2024.pdf, slide 34) and multiply the density grid by N_pl, but no cube row uses them; L1 is natural.
    11. The sources are silent on CF-cache cost models. CASA says only that filling the cache "can be time consuming" (tclean.xml L1099). The count N_cf and the per-cell bytes above are from casa-rs's index rules (plan §5.6) and my arithmetic; no corpus document quantifies A-projection kernel generation.
