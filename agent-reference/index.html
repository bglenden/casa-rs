    Agent Reference¶

    Truth class: normative Last reality check: 2026-10-20 Verification: just docs-check

    This is situational guidance for agents. Read only the section relevant to the task; root AGENTS.md remains the short always-loaded contract.

    CASA And C++ Oracles¶

    • Local CASA task runs use the CASA 6.7.6 release's Python, /Applications/CASA.app/Contents/MacOS/python3, which has casatasks and casatools. Scripts take CASA_RS_CASA_PYTHON to use another one.
    • Before implementing CASA/casacore behavior, inspect the corresponding upstream source path. Use targeted instrumentation on both implementations for parity investigations.

    plotms PNG Export¶

    For headless CASA plotms oracle PNGs, set:

    DISPLAY=${DISPLAY:-:99}
QT_QPA_PLATFORM=${QT_QPA_PLATFORM:-offscreen}
MPLBACKEND=${MPLBACKEND:-Agg}

    Then call casaplotms.plotms with showgui=False, plotfile=..., expformat="png", and overwrite=True.

    The local macOS CASA build does not use Xvfb, but plotms still requires DISPLAY. Do not run this CASA/Qt path in a shell sandbox that blocks sysctl CPU-feature queries: Qt may mis-detect arm64 NEON and print Incompatible processor. Use the normal user environment or an explicitly unsandboxed command runner.

    Shared Data Roots¶

    TESTING.md is the canonical resolver policy. Current workstation locations are:

    • Shared CASA C++ test data: CASA_RS_TESTDATA_ROOT, ../casatestdata, or ~/SoftwareProjects/casatestdata; long-gate preflight may select /Volumes/home/casatestdata when it contains the required paths.
    • Tutorial parity data: CASA_RS_TUTORIAL_DATA_ROOT/tutorial-parity/... or ~/SoftwareProjects/casa-tutorial-data/tutorial-parity/.... No copy is kept: the NAS mirrors were removed on 2026-10-23, and /Volumes/home/casa-rs/tutorial-data/ keeps only the download scripts and checksums to fetch the data from NRAO again.
    • Measures runtime data: an explicit root supplied to MeasuresRuntime::open, or a complete CASA_RS_MEASURESPATH / ~/.casa/data candidate selected by the application before opening the runtime. Discovery never installs data.
    • Small bundled real-MS CI fixtures: crates/casa-ms/tests/fixtures/.

    Slow, release, parity, and tutorial gates run shared-data preflight and report the selected root. Do not use /private/tmp as a canonical dataset location or add personal workstation archives as implicit default-gate fallbacks.

    Workstation Toolchain¶

    • Keep Xcode and the Command Line Tools on the same major version. If cc links fail with tapi error ... unknown architecture (for example while building fitsio-sys), xcrun is resolving a newer Command Line Tools SDK than Xcode's linker understands: update Xcode, or set SDKROOT=$(xcode-select -p)/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk.
    • After an Xcode update, run sudo xcodebuild -license accept and sudo xcodebuild -runFirstLaunch; until then git and cc fail.
    • FFTW: casa-fft finds FFTW through pkg-config, so a plain build links Homebrew's FFTW, which has no NEON kernels. Releases build the SIMD FFTW with scripts/build-fftw.sh. Performance work and timing evidence use the same build: on this workstation it is PKG_CONFIG_PATH=/Users/brianglendenning/SoftwareProjects/fftw-3.3.11-simd/lib/pkgconfig (built 2026-10-13). Check which FFTW a binary linked (the target/release/build/casa-fft-*/output link path, or nm BIN | grep -c n1fv_ for NEON codelets) before comparing timings, and link both sides of an A/B against the same FFTW.

    Cloud Sessions¶

    Claude Code cloud sessions run in a Linux container prepared by .claude/hooks/session-start.sh. Variables in the cloud environment's settings extend it; a session reads them when it starts.

    • TS_AUTHKEY joins the session to the owner's tailnet in the background (.claude/hooks/tailscale-up.sh; log in /var/log/tailscale-up.log). Use an ephemeral key. The container has no UDP, so peers are reached through Tailscale's relays: fine for SSH and small files, slow for bulk data.
    • CASA_RS_MAC_SSH_KEY lets the session work on the Mac mini (bg-mac-mini) as the owner: the macOS-only crates and Metal tests, the CASA oracle, or a second build beside the local one. scripts/mac-run.sh COMMAND mirrors the working tree to the mini and runs COMMAND there (--help for details).
    • The value is a private key without a passphrase whose public half is in the owner's ~/.ssh/authorized_keys on the mini, base64-encoded onto one line (base64 -i KEY | tr -d '\n' on macOS). CASA_RS_MAC_USER overrides the login name (default brianglendenning).
    • Copies live in ~/ext/SoftwareProjects/casa-rs-cloud/src/<branch>/ on the mini (the top of the ~/ext volume is owned by root) and share one target/ beside src/; CASA_RS_MAC_ROOT overrides the location. Remove a branch's copy with scripts/mac-run.sh --clean once its work is merged or pushed.
    • Commands run in a login shell, which reads ~/.zprofile and ~/.zshenv but not ~/.zshrc; settings the tests need, such as CASA_RS_MEASURESPATH, belong in the former. ~/.zshenv must print nothing, or rsync fails with "is your shell clean?". Stopping the script does not stop the command at once; it ends when it next writes output.
    • The script uses Homebrew's rsync on the mini when it is installed and the system openrsync otherwise; if openrsync refuses a transfer, brew install rsync there.
    • Run work that reads large data on the mini, next to the NAS and GLENDENNING, and bring back only results.
    • The NAS is not mounted in cloud sessions: the container's kernel has no SMB support and the NAS needs its own login. Reach its data from the mini, which does not mount it by default: the owner mounts it there (Finder or screen sharing) when a run needs it, and SSH logins see it under /Volumes while it stays mounted. Non-public datasets stay off the cloud container (AGENTS.md).

    Release And Installation¶

    • Smoke/release gate: just smoke
    • C++ interoperability gate: just release-cpp-interop
    • Performance evidence: just release-perf
    • Slow parity: scripts/test-slow.sh
    • Release: scripts/release.sh <version-or-flag>
    • Local installs: just install-local (or just install-local-suite)
    • Release install: just install-release <version>

    Use TESTING.md to decide when these heavier commands apply. Routine branch merges do not run release/tag-only gates.
