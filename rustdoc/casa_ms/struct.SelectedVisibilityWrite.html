Bounded in-place selected-visibility writer following ordinary casacore semantics.

The writer holds the MAIN write lock until it completes. Completion flushes every selected destination and releases the lock. A failure may leave partially written derived values, as an interrupted CASA write does; the next run recomputes them. No backup, staging column, rollback, snapshot, marker, or content digest is created.

Only destinations stored in TiledShapeStMan or TiledColumnStMan, the managers CASA and casa-rs store visibilities in, are written: their save patches the written rows’ tiles in place. Any other manager’s save rewrites its whole group from loaded cells, which holds every row of MAIN (ADR-0008), so retained_bytes and begin refuse such a destination before anything is changed.

pub fn begin( path: impl AsRef<Path>, targets: SelectedVisibilityWriteTargets, ) -> Result<Self, ObservationOwnerError>

Take the MAIN write lock and start an in-place write. MODEL_DATA is created when MAIN lacks it and filled with CASA’s initial model, as tclean creates it (initial_model_visibility: 1, and 0 in the cross hands), so rows the run does not predict hold that model.

A write of MODEL_DATA, created or not, first clears every field’s virtual model, and creating it the cached sort keywords, as CASA’s imager does (crate::scratch_columns::prepare_write).

The MeasurementSet is opened with retained read locks, and MAIN’s is then upgraded to the write lock. Both wait, as casacore’s do, for a conflicting lock another process holds. When another process holding a read lock waits to upgrade it too, the kernel refuses one of the two waits; if it is this one, the write fails with ObservationOwnerError::WriteLockUnavailable and releases its read locks. A virtual model under SOURCE is cleared under SOURCE’s write lock, which is not waited for while MAIN’s is held: when another process holds SOURCE, the write fails with the lock refusal and changes nothing.

A destination that cannot be written in bounded memory fails with ObservationOwnerError::UnboundedWriteDestination before the lock is taken. A write that fails once the lock is taken releases it as an abandoned write does, writing MAIN’s metadata alone.

Source

pub fn retained_bytes( path: impl AsRef<Path>, targets: SelectedVisibilityWriteTargets, ) -> Result<u64, ObservationOwnerError>

Heap bytes a write of targets to the MeasurementSet at path holds at most, which the pass that writes admits before it begins.

Per written column, that is a batch of queued cells of the MeasurementSet’s largest cell, the queue’s list of them, the row being written, and, while a batch is saved, the batch’s cells twice more (gathered for the save and staged by tile) with the column’s tile read and its tile written; the list holds its old and new buffers at once while it grows. Beside them are the batch’s row numbers and, while a missing MODEL_DATA is created, their data-description ids as read and as indices, and each data description’s initial model (a value per product). Tiles cached for reuse go to the process-wide table cache, charged on its own.

§Errors

When the MeasurementSet’s spectral-window, polarization or table descriptions cannot be read, and, as begin would, when a destination cannot be written in bounded memory or CORRECTED_DATA is missing: the pass that writes then fails before it runs.

pub fn complete(self) -> Result<(), ObservationOwnerError>

Flush the in-place write and release the MAIN write lock.

The selected cells were persisted in bounded row batches, so only the table metadata (a newly created MODEL_DATA) remains to flush.
